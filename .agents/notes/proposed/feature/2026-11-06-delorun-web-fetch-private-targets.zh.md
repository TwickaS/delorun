# Agent Note: web_fetch 拒绝回环、链路本地与私有网络目标

Status: proposed

[English](2026-11-06-delorun-web-fetch-private-targets.md) | 中文

## 问题

stock 抓取提供方不限制目标地址，因此 `web_fetch` 与访问公共主机一样，会访问回环地址、私有网络主机与云元数据地址。该提供方的 README 对此有明确说明。页面中的文本可以要求模型抓取某个 URL，因此一次抓取可能会访问本人网络中的服务或元数据地址，并把该服务的响应返回给模型，而本人并未决定要这样做。

## 提案

Delorun 的抓取防护将拒绝回环、链路本地与私有网络范围内的 `web_fetch` 目标，包括云元数据地址。该防护默认开启，本人可以在配置中将其关闭。被拒绝时，工具调用以 web 工具的结构化错误失败。`web_fetch` 工具仍保留在模型的工具列表中，这是 [web 能力决策](../../implemented/architecture/2026-06-24-web-capability-seam.zh.md) 在提供方无法运行时的要求。

防护将在请求发出之前检查目标。需要本地目标（例如回环上的开发服务器）的本人，将在配置中关闭防护。对等组合中该防护处于关闭状态，因此 stock 场景可以原样回放。

## 相关决策

[每步就绪决策](../../implemented/architecture/2026-09-27-web-search-offered-by-provider-readiness.zh.md) 仅在某个模型步骤无法通过认证时，才把 web 工具从该步骤中撤下。防护不会改变这一准入规则。

[出站代理决策](../../implemented/architecture/2026-08-27-outbound-proxy-policy.zh.md) 决定每个请求所走的路由。经代理发送的请求在代理处解析其目标，因此防护无法检查代理解析出的地址。

[DeepSeek Search 与 Fetch API 决策](../../implemented/feature/2026-10-15-deepseek-search-fetch-api.zh.md) 增加了一个抓取提供方，其服务会接收该 URL。防护将在提供方接收 URL 之前检查它，但无法检查该提供方服务解析出的地址。

本提案所改变的 stock 契约是 [web-fetch-http README](../../../../packages/web/web-fetch-http/README.zh.md)，其中写明该提供方会访问回环与私有网络主机。

## 考虑过的替代方案

**stock 行为。** stock 提供方不经询问即访问私有目标，本人无法看出页面引发的抓取访问了哪些目标。

**每次请求提示。** 对每个私有目标提示，会使这一决定变成一项例行审批，本人可能在未阅读目标的情况下就予以批准。带有明确开关的拒绝是更强的默认值。

## 验收标准

- 拒绝测试使用本地测试替身（一个回环监听器、一个链路本地地址与一个私有网络地址，均由测试控制），每个目标都以结构化错误被拒绝。该测试在防护存在之前失败，在防护存在之后通过。
- 关闭防护后，同一测试可以访问同样的目标。
- 对等组合中防护处于关闭状态，stock 抓取场景回放时没有任何差异。
- 被拒绝的 `web_fetch` 调用之后，该工具仍保留在后续请求的工具列表中。

## 风险

需要本地或私有目标的本人必须关闭防护，因为只要防护保持开启，合法的私有网络目标就会被拒绝。

防护只覆盖它能够检查的目标。远程抓取提供方与代理在其自身一侧解析目标，因此这一保证只涵盖拒绝测试所覆盖的地址，而不是抓取可能访问的每一个地址。

只有测试证明某个目标被拒绝时，拒绝才算已强制执行，因此每一类新目标都需要自己的拒绝测试，保证才能延伸到它。
