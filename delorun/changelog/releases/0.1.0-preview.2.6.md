# Delorun 0.1.0-preview.2.6

## Install and update
- Delorun is an agent harness that you shape to your own work: the themes, the sidebar, the plugins, the modes, even Delorun itself. It is built on DeepSeek Harness, runs its plugins and imports your chats, and adds a studio you open in a browser, a guided first run, undo for every change to your setup, protections for what agents may do, and reaching your home from your phone. This first public version, 0.1.0-preview.2.6, is described below: everything that differs from stock DeepSeek Harness, grouped by where you meet it.
- Run it with `npx delorun`. The first run checks the download against the signed release manifest and the public release log, then guides you through setup. Delorun runs on Linux (x64) and on Windows through WSL2.
- This is a preview. Releases are signed with preview keys through the 0.x versions, and no outside security review has taken place; [What you trust when you use Delorun](https://github.com/Delo-Run/delorun/blob/main/delorun/docs/guide/trust.md) says what that means. The rough edges you may meet are on the [known issues](https://github.com/Delo-Run/delorun/blob/main/delorun/docs/guide/known-issues.md) page, each with what to do.
- **Fixed:** The update report no longer says the release's freshness passed when it was never checked. A release installed with `delorun update --from` after you agreed that the release channel cannot confirm it is current now shows "freshness unchecked". `delorun update --yes` does not confirm it, and the studio asks you to tick that you want to update anyway, as it does when the release log could not be reached.
- **Fixed:** Updates no longer leave a pending review on Claude Code. The pack that adds Claude Code named the build's temporary folder in its dependency list, which differed with every build, so Changes showed a dependency change after each update. A pack now names the exact version of each package it carries and no longer ships the install state pnpm leaves behind, and the release build refuses a pack whose files name a folder on the build machine. An update also makes the release's own pack files the new baseline in Changes, once Delorun has checked them against the signed release, so it no longer leaves the previous release's files waiting for review, including the review the earlier build left behind. An edit of your own to a pack, or to any other file of it, still waits.
- **Fixed:** An update to a release that changes a protected setting no longer fails its health check and goes back. A release can turn a setting on in a row Delorun protects, such as External agents for live agents. An older release's update report could not name that change, so the health check refused it. The new release now reads its own signed files and the previous release's, accepts exactly the changes they bring, and shows them with the update's outcome in Settings → Updates. A setting you changed yourself, a weaker sandbox and a row that disappears still fail the check. The update report of this release and later ones names these changes before you update: `Delorun <version> changes the settings of the External agents row (delorun-agent-seats): turns on live agents.`
- **Fixed:** An update that waits for your running chats now notices when the last background job ends, as it does when a chat finishes. Before, a job that ended while the update waited could leave it waiting until it gave up with a timeout. A job that has already finished is no longer counted as running work, and an update still waits for every job and chat that is really running.

## Studio
- **Fixed:** Changes shows Undo on an action the agent ran with protection off only when Delorun can undo it. An action recorded without a profile version before and after it no longer has an Undo button that always refuses.
- **Fixed:** The reasoning-effort label beside the model name in the message box is readable in every look: it uses the same text colour as the other secondary text, at least 4.5:1 against the page, where it had been too faint in light looks.

## Safety and privacy
- With protection off, the agent's plugin tool works as it does in stock DeepSeek Harness once you give its single full-access approval: it installs, removes, turns on, configures, undoes and restores plugins, and plugins it installs or links reload when it saves them. Each of these is listed in Changes as a change that loaded without review, and you can undo it there or with `delorun changes undo`. With protection on, nothing changes: installs wait for your review, and turning a plugin on, undoing and restoring are left to you. A protection setting that cannot be read keeps every action held, as with protection on. A chat that already has full access or runs in dangerous mode gives no further prompt, as in DeepSeek Harness. Each action is recorded before it runs, undoing it keeps your own hand edits, your home patch and the plugins kept disabled, and going back to an earlier Delorun release still starts your profile.
- On a paired device, an action that asks you to confirm a second time, such as turning changes protection off, applying an agent's plugin request or applying a change the checks flagged, now needs Face ID or your PIN once. The confirmation you give after the first answer reuses it. Before, the first answer used it up and the confirmation asked again. The Face ID still covers exactly that action and nothing else of the request can change, it is used up when the action runs, and it still ends with its time limit.
- **Security:** The studio's setup import refuses a setup file whose contents claim far more space than a file of that size can hold, before it opens any of it. A crafted file can no longer make Delorun spend minutes and gigabytes of memory on it while your chats wait. The limits count every file path a setup names, so one large file named from many paths is refused too, and a plugin whose files cannot all be written is removed instead of left half written. A larger setup is still imported with `delorun setup import`, and the studio's message for a file or request that is too large now names the limit that applies.

## Reach
- **Fixed:** Reach over Tailscale now says what went wrong when Tailscale does not answer. A Tailscale that hangs, prints more than Delorun reads or cannot be started is reported as not answering, no longer as not installed, and Delorun no longer treats its serve rule as removed in that case. A large tailnet's status is read in full instead of being cut off and reported as not signed in. A reach option whose unlock time is above the cap Delorun allows now stops with that reason instead of staying on "starting", a failure of the reach status page no longer leaves the request hanging, and a check interval outside the range a timer takes is refused when Delorun loads it.

## Plugins
- **Fixed:** Turning on a plugin you made with Create a plugin, and importing a setup, now list the plugin installs and removals as asked by you. Before, Changes recorded them as "The agent asks to install".

## Commands
- **Fixed:** `delorun verify --release <version>` and `delorun <command> --help` reach the command that was named: the `delorun` launcher reads `--release` and `--help` only before the command word, and after `delorun repair`.
- **Fixed:** Pressing Ctrl-C, or sending a stop or hang-up signal, to the `delorun` command ends Delorun the way the program itself ends: the launcher passes a stop or hang-up signal on (Ctrl-C already reaches the program through your terminal), waits for the program to finish, and exits with its status, so the program no longer keeps running in your terminal after the prompt returns.

## Compatibility
- Delorun's own wording in the model's prompt (the Delorun name in the checkout and studio paragraphs, and the tool paragraphs sent only while a tool is offered) applies in the profiles Delorun starts; upstream's bare `dsh` web launcher shows DeepSeek Harness's own wording.
