# Delorun 0.1.0-preview.4

A device on your own Tailscale network is treated as your computer, so your phone stops asking for a PIN for ordinary work. Delorun now starts by itself when you log in, if you ask it to during setup. The spreadsheet and PDF previews open again, and a plugin switched off switches back on.

## Install and update
- **Fixed:** Building a release on a machine whose Docker engine is rootless now compiles the native addon as the container's own root user, which owns the mounted source, instead of as the caller's user id, which the rootless engine cannot write with. A rootful engine builds exactly as before.

## Setup
- `delorun setup` can make Delorun start by itself when you log in, through a systemd user unit, so the studio is there without a terminal. It sits beside the question about keeping Delorun running after the terminal closes, and it starts on No. The choice text says whether Delorun also starts when the machine boots with nobody logged in, which needs linger and which this computer may refuse. `delorun setup autostart` changes the answer later, and answering No removes the unit.
- `delorun stop` keeps Delorun stopped: the unit does not restart a home process you stopped, so it comes back when you start it again or the machine restarts.
- `delorun status` shows whether Delorun starts at login, and whether it also starts at boot.
- **Fixed:** The first-run guide's Welcome step says what it does: it asks for the language, and the next step connects a model. It used to promise both on one screen, where the model had no field.
- **Fixed:** `delorun setup`'s closing steps name the first-run guide's Models step as the place to add a model key, instead of a "welcome screen" that has no key field.
- **Fixed:** A start on a computer with no browser prints one line, `delorun open --print` and its link, instead of naming `delorun open` and then refusing it on the next line.

## Studio
- A check refuses an old spelling of Delorun, the old npm scope and an upstream name presented as Delorun's own, in the files Delorun owns. A file that must keep a spelling is listed with a reason, and the list only shrinks.
- A check refuses a Delorun screen that imports DeepSeek Harness's own button, dialog, pill or tab row, or draws a plain link, instead of the matching component from Delorun's design library. The screens that still do are listed with a reason, one entry per file and component, and each screen that moves to the library deletes its entries; the list only shrinks.
- A plugin can put its own list beside your chats instead of replacing them. The sidebar has a section seat above the chat list, so a plugin that offers its own tree — a project list, a saved-search list — appears next to your chats, search and shelves rather than in place of them. A plugin that tries to take over the whole browsing region is refused, and the refusal names the section seat to use instead.
- The Plugins screen's Delorun studio card now lists the studio plugins a person turns on — the cost meter and the Thinking tab — with their own switches, instead of leaving them only under Components on the bundle's own page. A switch writes through the plugin manager, so the profile records the choice and it survives a restart.
- The agents list is denser and easier to scan. Each agent sits on one line, the pin is a muted button that fills when pinned, and a control bar at the top carries the pane limit, Unpin all and the pane's own settings. The layout picker and the pinned-count line left the pane body for those settings. Past eight agents the finished ones fold behind one control that states how many are behind it, so a long list stays readable while every agent stays reachable.
- The consent and safety dialogs draw Delorun's own buttons and dialogs: the full-access consent, the MCP server review, the pairing notice, the device list, the trust panel and the permissions section. Every button gains the pressed shrink and the focus ring, and every dialog gains the action row and the warning tone.
- Settings, General, "How Delorun runs" shows a copy button beside each row's control instead of a bare monospace line under it. The button copies the terminal command that makes the same change, and its tooltip names that command and what pressing it does, such as "Copy the terminal command: delorun setup prompts". A keyboard reaches it, and the row's layout does not move.
- The Plugins screen's Experimental plugins group opens with a "Show experimental" button that states how many plugins sit behind it, instead of a small "More" text link. Codex subagent and Claude Code subagent no longer show a red "Problem" tag: they read as install-on-demand plugins, with their Add action and a quiet "Installs on demand" note.
- A subagent can run on any provider and model you have configured, including a different provider from the one its parent runs on. The Settings page's Model selection switch lets agents choose at all, and the list under it narrows the choice: leave every model unticked and any configured model is allowed. Each model runs at its own default reasoning effort unless the caller names one.
- **Fixed:** Attaching a file or image, and previewing a spreadsheet, a PDF or an Office document, work over a reach listener again. Each of them runs its work in a Worker built from a Blob, and the reach listener's Trusted Types policy admitted only plugin bundle paths, so the Worker constructor threw. The page now creates a `delorun-blob-worker` policy that admits a `blob:` URL whose origin is the page's own, and the four features mint their Worker URL through it. The policy still refuses another origin's blob URL, a `data:` URL and a plain string.
- **Fixed:** The spreadsheet and PDF previews open again. A change that gave both a shared helper made each pane load it as a separate file, and the studio cannot fetch one file from inside another, so neither pane opened. The shared helper now arrives with the pane instead, so each opens on its own.
- **Fixed:** The "Finish setup" line at the sidebar's foot pads its text by the sidebar's own inset, so the label no longer touches the bar's edges, and it carries a × that dismisses it. The dismissal is kept with the guide's progress, so it survives a reload, and it lasts only until a step the person has not dismissed arrives.
- **Fixed:** In a pinned PWA on iOS the studio's surface now reaches the physical top and bottom edges. The shell was sized to `visualViewport.height`, which on iOS stops at the status bar and the home indicator; it now takes the screen, and follows the visual viewport only while the on-screen keyboard shortens it, so the composer still stays above the keyboard.
- **Fixed:** The "Add a model key to start chatting" line above the message box now has the message box's own corner radius, so the two read as one surface rather than two different components.
- **Fixed:** Closing Multiview with its button now keeps it closed. A chat that hands work to a new agent no longer reopens Multiview after you have closed it; the new agent is still pinned, and the icon shows its count and its amber dot. Opening Multiview again, from the icon, the agents list or the keyboard command, lets the next hand-off open it as before. The setting that opens Multiview on every hand-off still turns that off entirely, and turning it on no longer overrides a close you made.
- **Fixed:** On an iPhone the studio's colour reaches the screen's edges: the status bar, the home indicator and the area beside Safari's bars take the colour of the surface at that edge, so the sidebar's header gradient, a chat, Settings and a dialog each continue into the system chrome with no dark band or seam. The colour follows the view as it changes, including the sidebar opening over a chat.
- **Fixed:** The studio fills the screen as an installed app: the sidebar's header and foot and the chat's composer reach the physical edges, and their content stays clear of the notch and the home indicator in both orientations.
- **Fixed:** The studio no longer bounces when a list is dragged past its end, and the composer stays above the on-screen keyboard while typing.
- **Fixed:** The installed app launches on the studio's own dark surface instead of a white flash, and its home-screen name is Delorun.
- **Fixed:** A plugin switched off in Plugins switches back on. A third-party plugin whose bundle only adds a setting to a row Delorun protects, as `dsh-unlag` adds `base` to the reload row, switched off without complaint and was then refused as `management-required` each time it was switched on, although Plugins showed it as not protected. Both directions now judge the same thing: a change may add a setting to a protected row and may not disable the row, replace it, drop it, give its id to another row, or change or remove a setting the profile ships for it.
- **Fixed:** A filled button's label is readable on every accent: the label follows the accent's own ink, so Cobalt, Moss and Mono in light no longer draw dark text on a dark fill. Peach keeps the dark label it had.
- **Fixed:** A chat with several panes open stays smooth while answers stream in. Following the newest message used to measure the transcript's scrollport three times for every streamed piece of text, and each measurement made the browser recalculate the page's layout before it could answer, so six streaming panes cost about three times the recalculation of a closed layout. It measures once and passes that down, so the work is a third of what it was.
- **Fixed:** The sidebar's left edge is one line from top to bottom: the search field, the chat titles, the shelf labels, the folder names and the "More" button all start at the same inset, and the header's buttons, the panel toggle and the foot's buttons share one right edge and one control size. The working indicator is a small ring that turns while a chat works, instead of a frozen arc.
- **Fixed:** A long folder name in New workspace's folder search stays on one line and is cut with an ellipsis, and every row keeps the same compact height whatever the names are. The full path is the row's tooltip.

## Safety and privacy
- The consent before a delegated Claude Code or Codex run now says the agent reads the workspace's own project settings, including any MCP servers the project declares, under its own rules rather than Delorun's MCP consent. What the agent can read does not change; the consent states it.
- Your phone stops asking for a PIN or Face ID for ordinary work. When a request comes from a device on your own Tailscale network, Delorun asks Tailscale who that device is and treats it as your own computer, so changing settings, managing plugins, opening a folder picker and the rest of the everyday actions happen without a prompt. A terminal still asks, because a shell is what could reach the things that decide who can get in, and so does allowing full access for a chat. Approving a device, adding a passkey, the PIN, turning remote access on or off and the other actions that decide who can reach your studio stay at your computer. If Tailscale cannot say who the device is — it is not running, it does not know the address, or the device has left your network — Delorun asks for the PIN or Face ID as it does today rather than assuming.
- The Security panel answers at a glance: the basic view shows the headline and the five rows, each with its status and one sentence, and the button that fixes a row stays beside it, so the whole answer fits without scrolling on a phone or a desktop. What a row means, why it has its colour, whether it is your choice, when each check last ran, Check now and the lists behind each row are in Advanced, which may scroll.
- **Fixed:** A value set in the home patch (`~/.delorun/cordis.patch.yml`) is now in the setup versions a person saves and switches back to. Before, a version held only the profile's own files, so a value set in the home layer had no restore point through the studio's versions and a switch back left it as it was. A version now holds both patch layers, a switch writes both, and the preview says when the home layer would change. A value for a secret field in the home patch is refused by the same check that refuses one in the profile patch, so it never enters a version.
- **Fixed:** A folder inside a workspace inherits that workspace's network setting. A chat whose working folder is a subfolder of a workspace set to Off no longer falls through to the deployment default, so a command run there cannot reach the network the workspace was closed to. A nested workspace keeps its own setting.
- **Fixed:** A phone reaches the studio's own routes when the reach policy already allows the action they serve. Downloading a chat's Markdown copy, the Changes review tab, a plugin's artwork and a delivered file's card no longer answer 403 to an approved device. The chat archive still needs the `/export` command's confirmation, and the two routes that open a file on the computer's own screen stay at the computer.

## Plugins
- A plugin that declares `engines.delorun` is now checked on that range alone: its `engines.dsh` and DeepSeek Harness peer ranges are not checked on Delorun, at install, at start, in the update report and by `delorun plugin check`. A plugin without `engines.delorun` is checked as before, and stock DeepSeek Harness ignores `engines.delorun`, so one package can declare both and run on both. `delorun plugin check` says which range decided, and `--json` prints that as one record for tools.
- **Fixed:** A plugin's Delorun requirement is checked against the Delorun that is running, and a caller that asks for the DeepSeek Harness axis alone gets only that axis. The update report decides each axis separately, so a plugin whose `engines.delorun` the target does not satisfy is now reported on the Delorun axis instead of being read as a Delorun mismatch while the Harness axis was being decided.
- **Fixed:** A start no longer logs that it could not check the profile for plugin keys while another change was writing the profile: a change that runs inside a writer's own hold takes the profile's write lock once, so the start keeps the profile history version that records the change, and two separate writers still take turns.

## Commands
- The machine-wide queue now holds new grants only while the machine has been saturated for a minute, read from the kernel's pressure stall information: cpu, memory or disk over 90% of the last 60 s. The machine is meant to be used, so a busy merge tier never trips it; a spike of a few seconds never trips it either, and holders are never interrupted. A machine whose kernel reports no pressure is never held. `run-checks --queue` shows the alarm and its figures.
- The queue also reports a slot count set far above the machine's CPUs, such as a figure left over from a larger machine, rather than silently overfilling the machine with it.
- The machine queue reserves what a check declares, not the share of the budget its slots would buy. A check that declares 4 GiB is reserved 4 GiB, where it was reserved 4.6 times that on a 9-slot budget, so the runs waiting behind a build start beside it instead of waiting for memory the build never used. A check that declares its memory per worker keeps scaling with its workers.
- The queue measures the machine rather than assuming one. The memory kept outside the runs is an eighth of the machine rather than a 2 GiB floor, `DELORUN_CHECKS_MEMORY_GIB` overrides the figure, and `run-checks --queue` prints the derivation. The disk-heavy places follow the disk: four on a disk that reports no seek cost, three on a spinning one, and `DELORUN_CHECKS_DISK_RUNS` overrides both.
- A push from a worktree is refused while the shared checkout holds uncommitted changes to tracked files, and no script, hook or workflow may skip a git hook with `--no-verify` or disable Lefthook. Both refusals name what to fix, so a stray write in the shared checkout or a skipped hook stops the push instead of reaching the trunk.
- **Fixed:** A check run now asks the machine-wide queue for the slots its own memory ceiling can keep busy, rather than the sum of every check's CPUs. A merge-tier push of 96 checks used to reserve all 64 slots while using about 21 CPUs of them, so every other lane waited behind a reservation the run could not spend; it now asks for 21 and the lanes start beside it.
- **Fixed:** A release cut after a signing-key rotation no longer stops part-way. The cut now accepts the whole chain of trust roots, oldest first, so it passes both the root a signer's state already trusts and the new one; only the newest is used to probe the release log.
- **Fixed:** A publish no longer fails when the storage service drops a connection under load. Each store call is tried up to three times with a growing pause, and an answer the bucket actually gives is never retried.
- **Fixed:** **Fixed:** The documentation and catalogue gates pass again. The persistence catalogue, the event producer and consumer lists, the capability seams and the Cordis API catalogue are regenerated from the code they describe, and the home-patch service is classified for the package-dependency gate.
- **Fixed:** The check that builds the product website reports a checkout without the site's source pictures as a limit of that machine rather than a failure of the change. The pictures are real screenshots of the studio and are not in the repository, so the check now declines with a message naming `SITE_PICTURES_DIR` and the folder to point it at, instead of failing the build with the same message as an error.

## Compatibility
- **Fixed:** The compatibility bench closes the first-use dialogs topmost first, so a plugin that opens a dialog of its own before the studio's first-run guide appears is exercised instead of stuck: the guide painted above the plugin's dialog, the click aimed at the first dialog in the page was intercepted, and every stage that drives the browser failed on it.
- **Fixed:** The bench asks the host for a sign-in link for up to fifteen seconds after a studio start, because the studio answers on its port before the home process reports a host and `delorun open --print` then answers that no host is running.
