# Delorun 0.1.0-preview.1.7

## Studio
- The setup guide's Welcome step shows the languages as two large tiles, each named in its own language, with a small picture of the studio below that switches language as you pick.
- Every step of the setup guide uses the window's space: Phone access explains how it is set up and what a phone can do, Workspace explains what a workspace is for with an example folder of each kind, and Look shows its themes in two full rows.
- The setup guide's buttons read "Skip step" and "Complete setup later"; Finish setup in the sidebar footer brings the guide back.
- The sidebar footer is one aligned row of icons, with Finish setup on its own line above it instead of a second, right-aligned row.
- The setup guide's Models step explains "How does Delorun know?" once for all the providers it found, instead of repeating it under each one.
- In the Recommended plugins step, each row has one right-aligned slot that goes from a secondary Add button with a plus, to Adding with the download's progress, to Added, all the same width so the row does not move. More and Less use the muted link style.
- Adding plugins in the setup guide shows in the downloads panel straight away, and a plugin that is being added keeps its state when the list is read again, so a quick run of Add clicks queues every one of them.

## Safety and privacy
- **Fixed:** A newly approved phone can no longer open or type in a terminal during the 15 minutes after you approve it at the computer. A terminal is a shell on your computer outside the sandbox, so from a phone it now always needs an unlock: a code from the computer, your PIN or the unlock method you chose. Setting up from the phone in those 15 minutes still needs no unlock.
- **Security:** Browser refuses to save or upload a file whose path really lies outside the chat's folder. Playwright's own check compares paths as text, so a link inside a project could lead a screenshot, PDF or upload somewhere else on the computer. The agent is told to use a path inside the chat's folder. If a project's `.playwright-mcp` is itself a link to somewhere else, Browser's tools stop until you remove it, because downloads and default-named files would follow it.
- **Security:** Browser no longer gives the agent Playwright's `browser_run_code_unsafe` tool. It ran code the agent wrote on your computer, outside the page and outside the sandbox.
- **Security:** The folder in the Delorun home that Browser's server runs in is kept private to you, including when it already existed with wider access.

## Plugins
- Browser uses Google Chrome when you have it installed, so it needs no download and no setup. Chrome runs in a fresh profile of its own, never your Chrome profile. Without Chrome, Browser uses Playwright's Chromium as before, and Plugins shows "Needs setup · Chromium download" until that build is there. A Delorun update can need a new Chromium download only in that case. To always use one of the two, set `browser: chrome` or `browser: chromium` on the `browser-use-playwright-mcp` row. Restart Delorun after you install or remove Chrome.
- Browser asks you to allow its playwright-mcp server once, not once for each project folder. The server now runs in one folder of the Delorun home for every chat, so the same exact command is what you allow, and switching between projects does not ask again.
- Screenshots, PDFs and other files Browser saves go into a hidden `.playwright-mcp` folder in the chat's project, and the agent gets a link to each one. Delorun gives that folder its own `.gitignore`, so Git leaves the files out of commits, including in a `.playwright-mcp` folder you already have that has none. A `.gitignore` already in that folder, and your project's `.gitignore`, are left as they are.
- **Fixed:** Browser now says "Needs setup · Chromium download" in Plugins when the Chromium build its Playwright expects is missing, with the command that downloads that exact build. Before, it said Browser was ready whenever Chrome was installed. A browser step that still finds the build missing fails with one short message telling the agent to stop and ask you to finish Browser setup in Plugins. In 0.1.0-preview.1.6 the agent kept trying other tools instead, at length.
- **Fixed:** New chats start again after you add the Browser pack and before you allow its playwright-mcp server; in 0.1.0-preview.1.6 every new chat failed with "McpConsentRefusedError" until the server was allowed. The chat now starts without the browser tools, home.log notes why, and the notice reads "MCP tools are off until you allow playwright-mcp" with the action that reviews and allows it. Once allowed, the server starts in your next new chat.
- **Fixed:** Plugins no longer shows "Update available" and an Update button on a plugin pack you installed (such as Claude Code or Codex) when it already runs the version this Delorun offers. The tag compared the reviewed copy in Changes with the pack folder; a pack whose approved source is the offered pack folder now counts as the same source, and a different version still shows the tag.
- **Fixed:** Adding several plugin packs no longer stalls for two minutes at a time or fails with "timed out waiting for the writer lock". Packs still download two at a time, but install one after another, and Delorun reads a plugin's folder before it locks the profile, so other changes to the profile no longer wait for that read.
