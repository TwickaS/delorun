# @delorun/plugin-new-workspace

[English](README.md) | 中文

Delorun 的新建工作区流程。Host 端提供流程各屏调用的路由：从哪里开始查找、有界的文件夹搜索、单个文件夹的预览、添加已有文件夹、新建文件夹（可选创建 Git 仓库）、从 Git 克隆（可选分支），以及每个工作区的默认设置。它还让工作区里每个新对话以该工作区的模型开始。它的 Studio 端是调用这些路由的对话框。

## 路由

每条路由都是 `/api/delorunNewWorkspace` 下的精确 `POST`，仅在上游的工作区注册表存在时提供。每条路由都应答本机电脑；已配对的设备只有在持有解锁时才能访问（否则返回 `ELEVATION_REQUIRED`）；其他任何来源在读取请求体之前就被拒绝，返回 `LOOPBACK_REQUIRED`。四条会改变状态的路由（`add`、`create`、`clone`、`setDefaults`）会续期设备的解锁。

| 路由 | 请求体 | 应答 |
| --- | --- | --- |
| `.places` | 无 | 文件夹仍存在的最近工作区、存在于某个根目录内的建议文件夹、主文件夹，以及新文件夹的默认位置。 |
| `.search` | `{ query }`，1 到 100 个字符 | 名称包含查询内容（不区分大小写）的文件夹，最多 50 个，由近及远；以及搜索停止的原因：`complete`、`limit` 或 `time`。 |
| `.preview` | `{ path }` | 文件夹是空的、代码还是普通文件；其标记文件指明的技术栈（Node.js、TypeScript、Deno、Python、Rust、Go、Java、Ruby、PHP、.NET、Swift、Elixir、C 和 C++）；是否为 Git 仓库、所在分支，以及最近一次提交的主题和时间；是否有 `AGENTS.md`；以及前 24 个可见名称（文件夹在前），每个文件附以字节计的大小。 |
| `.add` | `{ path }` | `added`，带工作区 id、规范路径和类型；或 `refused`，带原因。 |
| `.create` | `{ parent, name, git }` | 创建 `parent/name` 并注册；带 `git` 时运行 `git init` 并写入初始 `.gitignore`。 |
| `.clone`、`.cloneStatus` | `{ url, parent, name, branch? }`，然后 `{ job }` | 开始克隆到 `parent/name` 并报告进度，然后注册该文件夹。 |
| `.defaults`、`.setDefaults` | `{ path }`，然后 `{ path, defaults }` | 单个工作区的模型、思考强度和浏览器选择。 |

## 工作区可以放在哪里

每个路径都检查两次：一次对照 Delorun 从不添加的文件夹（主文件夹本身、Delorun 主目录、原版主目录，以及 `@delorun/home` 的 `workspaceLocationProblem` 列出的系统文件夹）；对搜索、预览、新文件夹和克隆，再对照配置的 `roots`，并解析符号链接。新文件夹或克隆的父文件夹缺失时会被创建，创建后再检查一次，因此期间被植入的链接会被拒绝。拒绝时会说明原因，且不创建任何东西。

预览读取文件夹的顶层名称、每个所列文件的大小、`.git/HEAD`，并且对于其 `.git` 是其中真实文件夹的仓库，读取最近一次提交的主题和时间，在 `searchTimeMs` 内最多读取 2000 个条目；不打开任何文件的内容，不跟随链接。该提交来自一次 `git log -1` 运行，运行时关闭用户和系统的 Git 配置，忽略替换引用，不做惰性获取，也不使用传输（部分克隆缺失的对象永远不会被获取，所以它的 `core.sshCommand` 从不启动），使 Git 不向文件夹上方查找、也不把它当作裸仓库，覆盖仓库的 `core.fsmonitor`、`core.hooksPath` 和 `log.showSignature`，不出现提示，限时两秒，输出限 4 KB。Host 上同时运行的此类运行最多三个，另有 24 个排队等候；超出的请求得不到提交。`.git/objects/info/alternates` 指明其他文件夹用来读取对象的仓库，得不到提交。主题中的格式字符和控制字符（包括双向标记）会被移除。搜索从每个根目录广度优先遍历，最深 `searchDepth` 层、最多 `searchFolders` 个文件夹、最长 `searchTimeMs`。它从不跟随链接，并跳过隐藏文件夹、依赖和构建文件夹（`node_modules`、`vendor`、`dist`、`target`、`venv` 等）、Delorun 主目录和原版主目录。

## Git

`create` 和 `clone` 运行 Git 时关闭钩子、LFS 过滤器和个人模板，不读取系统或全局配置，没有 askpass 程序，也不在终端提示。克隆接受不含用户名或密码的 `https` 地址，以及 `ssh` 和 scp 风格的地址；它跳过子模块，检出时取消所有 `filter` 属性，完成后删除 `.git/info/attributes`。分支名在 Git 运行前按 Git 的规则检查。`@delorun/plugin-workspaces` 的导入克隆使用同一套 `cloneArguments` 和 `createCloneTemplate` 构建参数。

## 每个工作区的模型和浏览器

`.setDefaults` 把单个工作区的模型（`provider`、`model`，可选 `reasoningEffort`）和浏览器选择保存在 `<Delorun 主目录>/secrets/new-workspace/defaults.json`，权限 0600，以文件夹的真实路径为键，并使用锁文件。同一文件还记录上一次新文件夹或克隆所在的文件夹，`.places` 会把它作为下一次的位置。

当顶层对话在默认设置含有模型的工作区里开始时，插件会在第一个请求之前追加上游的 `model/selection` 事件，因此对话日志会记录它起始使用的模型。恢复、分叉或委派的对话、已经记录了模型的对话，以及模型提供方未连接的工作区都不受影响；最后一种情况会写入日志。

插件还提供 `browserUseAdmission`，浏览器插件包的隔离浏览器（`@deepseek-ai/dsh-experimental-browser-use-playwright-mcp`）在每个对话开始时和每次浏览器工具调用时都会询问它。对话所在文件夹及其上级中，最近一个保存了浏览器选择的工作区起决定作用：选择“不使用浏览器”时，该对话不会获得浏览器服务器，其浏览器工具调用会被拒绝；因此，位于“不使用浏览器”工作区之内、设为“隔离浏览器”的工作区仍会获得浏览器。这些选择保存在内存中，在提供服务之前读取一次，并在每次 `.setDefaults` 更改后重新读取；回答发生变化的每个正在运行的对话都会通过 `browser-use/admission-changed` 事件报告，因此其浏览器服务器会立即停止或启动，新对话则遵循新的选择。已存在的存储文件无法读取时，任何对话都不会获得隔离浏览器，日志会说明原因。此插件的行关闭或失败时，没有任何插件提供准入，每个对话都会获得隔离浏览器，无论保存了什么选择。“不使用浏览器”只针对隔离浏览器：在该工作区中仍可请求使用本人自己的浏览器（`@delorun/browser-use-browse`、`use_my_browser`），因为每次使用都需要本人为该对话单独批准。

## 配置

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `roots` | `['~']` | 新文件夹和克隆可以放置的位置，以及搜索的范围。 |
| `suggested` | `~/Projects`、`~/src`、`~/code`、`~/Documents`、`~/Desktop` | 作为起点提供的文件夹（存在于某个根目录内时）。 |
| `firstParent` | `~/Projects` | 用户还没有新建过文件夹时，新文件夹或克隆的位置；首次使用时创建。 |
| `searchDepth` | 4 | 搜索在每个根目录下查找的层数。 |
| `searchFolders` | 20000 | 一次搜索最多读取的文件夹数。 |
| `searchTimeMs` | 2000 | 一次搜索或一次预览读取的最长时间。 |
| `cloneTimeoutMs` | 600000 | 一次克隆的最长时间。 |

## Studio 端

它只在 Delorun 外观开启时加载；原版外观沿用上游的流程。它以优先级 -1（低于上游的选择器）占用上游的三个目录流程插槽，因此侧栏的“添加工作区”、新对话的工作区选择器和首页的工作区选项都会打开这个对话框，并把工作区的文件夹作为选中的文件夹交回，由上游接收并打开。`ctx.delorunNewWorkspace.open({ from })` 打开一个大对话框，尺寸为 `min(1040px, 92vw)` 乘 `min(720px, 88vh)`，手机上为全屏，并以工作区的 id、文件夹及文件夹内容（`code`、`files` 或 `empty`；新文件夹启动 Git 时为 `code`，否则为 `empty`）解析为 `created`，或解析为 `cancelled`。已有一个流程打开时再次调用 `open`，会把前一个解析为 `cancelled`。关闭对话框不会取消克隆：克隆仍在 Host 上继续运行。

第 1 屏询问如何开始（新文件夹、本机上的文件夹、从 Git 克隆），并列出最近的工作区，一次点击即可使用。第 2 屏取决于所选卡片。文件夹浏览器只有一个顶行：从“主文件夹”起可点击的路径层级、文件夹名称搜索，以及一个“新文件夹”图标按钮。文件夹占满宽度，各带一条从其预览读取的提示（其技术栈或类型及其 Git 分支），直到选中某个文件夹；然后在列表旁打开它的摘要，含其技术栈标签、分支和最近一次提交、顶层文件及其大小，以及“使用此文件夹”。它也用于为新文件夹或克隆选择位置。在手机上，文件夹占满屏幕，摘要作为带“返回”的全屏步骤打开。其他屏幕随内容大小适配，因此对话框没有空的下半部分；文件夹浏览器保持完整高度。新文件夹屏接受名称、位置，以及是否启动 Git（默认勾选）。克隆屏接受地址、可选分支、位置和名称，并启动克隆，克隆在后续屏幕显示期间继续运行。第 2 屏的“继续”进入浏览器屏，此时还没有创建任何内容。

第 3 屏是浏览器：“此工作区中的智能体可以使用网页浏览器吗？”是来自 `@delorun/browser-setup` 的一组选项，设置向导的“浏览器”步骤绘制的是同一个组件。可以选择“独立浏览器”和“不使用浏览器”；“使用我的浏览器”显示为禁用并带有“预览”标记，不记录任何内容。当 Host 列出浏览器插件包时，选项默认是“独立浏览器”，否则是“不使用浏览器”，并在加载过程中跟随 Host 的报告，直到用户做出选择；一旦选择就保持不变。选中“独立浏览器”时，该屏会说明浏览器是否已就绪：它在该屏打开时以及窗口重新获得焦点时读取 Host 的需求检查，读取失败时提供“重试”，并给出满足某项需求的设置分区或命令。当插件包不在配置中时，该屏显示“此主目录中的‘浏览器’插件已关闭。”和“打开插件”按钮，仅在页面有设置外壳时提供。该选择与模型一起保存到工作区，选择“不使用浏览器”时，该工作区的对话不会获得隔离浏览器（见[每个工作区的模型和浏览器](#each-workspaces-model-and-browser)）。

第 4 屏是模型：“这里的新对话使用”一个模型和一个思考级别，读取自 Studio 的 `remote.session` 模型目录，并预填主目录的默认值（“<模型>（你的默认）”）。思考级别列出所选模型支持的级别。无法读取目录时，该屏说明对话会使用主目录的模型，“继续”仍可使用。无论是否更改，工作区都会保存它所显示的模型和级别，因此主目录的默认值之后改变时，它仍保留这些；没有目录时不保存模型。第 5 屏是安全：“更改此文件夹中的文件”（默认选中，推荐）或“完全访问”（会为此工作区询问一次），然后是命令的互联网访问：开放（默认）、仅我列出的网站（每行一个主机名，按主机名检查，最多 200 个）或关闭。这里不提供只读。模型屏和安全屏末尾都有同一段说明，介绍单个对话可以切换什么（模型、权限，以及网络对整个工作区保持不变）。第 3 屏和第 4 屏提供“立即创建”，以目前已做的选择完成流程；最后一屏的主按钮是“创建工作区”。在第 1 屏选择的最近工作区会按原样添加，并保留它已有的内容。

完成时先创建工作区，再按固定顺序进行设置，页脚显示“正在设置…”：先用保存的模型和浏览器选择，一次调用 `.setDefaults`；然后，当网络不是“开放”时，调用主目录自己的 `POST /api/delorunNetwork.set`，内容为 `{ path, network: { access, hosts } }`；然后，若选择了完全访问，调用 `ctx.delorunFullAccess.askForWorkspace(path)`；最后才解析为 `created`。路径是 Host 返回的规范路径。失败的步骤会在最后一个视图中就地显示，工作区仍可通过“打开工作区”按钮打开（关闭该视图同样会打开它）；被拒绝的同意会让工作区保持在“更改文件”并且不显示提示，没有同意服务的页面则提示稍后在对话的权限菜单中开启完全访问。文件夹、名称或克隆被拒绝时，会带着原因回到第 2 屏。

每一屏打开时都已选好安全的选项。路由的回答按其 wire schema 解析，失败以值的形式返回：`locked` 通过 `remote/call-denied` 请求 Studio 的解锁提示，`refused-arrival` 表示这一步需要在电脑前进行，每个拒绝都以一句话就地显示。路径把主文件夹显示为 `~`，不显示这台电脑的其他任何信息。在手机上，对话框占满整个屏幕：卡片纵向堆叠，文件夹浏览器一次只显示一列，页脚按钮在“返回”“立即创建”和“继续”放得下时共用一行，放不下时“立即创建”单独占上方一行。

## 测试

`tests/routes.spec.ts` 挂载插件，并对每条路由检查被拒绝的来源、已锁定的设备和本机电脑。`create.spec.ts`、`clone.spec.ts`、`places.spec.ts` 和 `search.spec.ts` 覆盖主文件夹、Delorun 主目录、根目录之外的文件夹以及离开根目录的链接；`defaults.spec.ts` 覆盖存储文件的权限和格式，以及种子写入的条件。 Studio 端的规格是 `tests/*.client.spec.tsx`（对话框、API 客户端和服务）、`finish-flow.client.spec.tsx`（包括设置顺序）和 `flow.spec.ts`（流程的状态机）；`setup.client.spec.tsx` 覆盖模型屏、安全屏和各条完成路径，`browser.client.spec.tsx` 覆盖浏览器屏，`models.client.spec.tsx` 覆盖目录映射和主机列表。 `browser-admission.spec.ts` 覆盖准入：位于选择了“不使用浏览器”的工作区或其内部文件夹中的对话被拒绝，最近的工作区的选择起决定作用，无法读取的存储不准入任何对话，更改后的选择作用于下一个对话，并为回答发生变化的每个正在运行的对话报告。
