# @delorun/bundle-local

[English](README.md) | 中文

> 英文页面是当前版本；本页可能落后于它。

## 摘要

`@delorun/bundle-local` 是 Delorun 的 CLI profile 在上游 `web` profile 模板之后加入的组合包。它的 patch 保存 Delorun 的本地集成行，每一行的理由都列在 [`LOCAL_ROWS`](src/rows.ts) 中，因此 Delorun 的 CLI profile 在组合上游的 web profile 时，只改变或新增这些行，其他一概不变。它关闭上游的两个选择加入项，即 DeepSeek 的会话日志上传与桌面应用的分析，并在设置中新增“隐私”分区（本人在其中经同意对话框后逐项打开，也可再关闭）、“关于”分区以及发布检查所在的“通用”行（[C11](../../docs/contracts/c11-setup-answers.zh.md)）。它挂载 Delorun 的同意与守卫插件并打开其开关：指令层写入同意（连同对已批准插件的写入同意）、MCP 添加时同意、带有唯一一次完全访问同意的按工作区权限默认值、计划任务同意、抓取防护，以及留待审查的插件变更；它还挂载更新闸门，在 `delorun update` 或 `delorun stop` 等待运行中的 chat 结束时拒绝新的轮次；并在上游的 sandbox 行上设置 C1 的 home 保护，使受限命令在 Linux 与 macOS 上无法读取 home 的 `secrets/` 之下的同意存储，Windows 运行器不隔离读取。它在上游的 `workspace-controller` 行上，把 studio 首次使用的工作区所在文件夹设为 `delorun start` 解析出的文件夹，使上游的文档目录查找找不到文档目录时，studio 仍有默认工作区。只有 CLI profile 加载本组合包：`delorun headless` 加载 [`@delorun/bundle-headless`](../bundle-headless/README.zh.md)，它挂载同样的同意与守卫插件，以同样的方式保护它们，并关闭会话日志上传；`delorun plugin` 与桌面应用运行上游自己的 profile，其中这些行都不适用，会话日志上传保持打开。它还打开上游的一次性启动令牌，因此 studio 登录链接只能在一分钟内使用一次。

## 使用本组合包

- **组合包列表。**[`DELORUN_PROFILE_BUNDLES`](src/profile.ts) 从 `@delorun/bundle-local/profile` 导出，是 Delorun CLI profile 有序的 `dsh.profile.bundles` 列表：先是上游的 `web` 模板（从 `@deepseek-ai/dsh-official-bundles` 读取），然后是 `@delorun/bundle-local`，再然后是挂载 studio 附加功能的 [`@delorun/bundle-studio`](../bundle-studio/README.zh.md)（`STUDIO_BUNDLE`）。上游自己的模板不列出本组合包，因此 `dsh --profile web` 与记录会话回放只组合上游的组合包。
- **`delorun` 的职责。**`delorun` 创建 `~/.delorun/profiles/` 之下的 CLI profile（[C1](../../docs/contracts/c01-home-layout.zh.md#profiles)），把 `DELORUN_PROFILE_BUNDLES` 写入它创建的每个 CLI profile；当上游的 profile 加载器在 `skippedBundles` 中报告本组合包时，它拒绝启动该 CLI profile，因为隐私默认值只在本组合包加载时才成立。本包自身两件事都不做。
- **层顺序。**本组合包在每个上游组合包之后、profile 自身的 `cordis.patch.yml`、home patch 与 `--patch` overlay 之前生效，因此本人在 profile 中的设置仍然优先于此处的行（[上游的 profile 层](../../../apps/cli/README.zh.md#profiles)）。“隐私”分区写入 profile 的 `cordis.patch.yml`。
- **读取组合结果。**`dsh --profile <name> --dump-config` 会在每个 `# ==` 行之下打印全部组合后的行；该行写明插入此行的组合包，以及修补过此行的每个组合包。本组合包写入的行，在那里写作 `@delorun/bundle-local`。
- **加载。**本组合包未声明 `engines.dsh` 范围，也没有上游的对等依赖，因此版本变更之后，上游的兼容性检查从不会跳过它；若 profile 的组合包列表列出了它却无法解析，则会把该组合包报告为已跳过。
- **更新检查。**`delorun-update-check` 行挂载 [`@delorun/bundle-local/update-check`](src/update-check.ts)，即 C16 开关 `update_check`，它提供 `delorunUpdateCheck` 服务，并在 `GET /api/delorunUpdateCheck.notice` 提供其提示。无论开关打开与否，它还提供 `GET /api/delorunUpdateCheck.channel`，返回 `{ host }`：即以 `--channel-origin` 构建的启动器记录在 `trust/channel.json` 中的通道来源的主机；在生产通道上返回 `null`。这样“通用”行的文案就能写明检查所联系的主机（[C3](../../docs/contracts/c03-update-report.zh.md#update-check)）。`delorun` 的 Host 以 `attach(source)` 挂接该检查，其返回的销毁器会解除挂接；随后该行在上一次检查距今至少 `intervalHours`（默认 24）时立即运行一次检查，此后每隔一个间隔再运行一次，期限为 `timeoutSeconds`（默认 15），并且从不等待某次检查完成。同一时间只挂接一个检查。开关关闭时（插件的默认值），它不提供服务、不注册路由，也不运行检查；“设置 → 通用 → 更新”会在 profile 自己的 patch 中把它关闭。
- **The trust bill.** The `delorun-trust` row mounts [`@delorun/bundle-local/trust`](src/trust.ts), which provides the `delorunTrust` service and serves the trust bill (`@delorun/bundle-local/trust-bill`, contract [C15](../../docs/contracts/c15-verification-checks.zh.md)) at `GET /api/delorunTrust.bill` as `{ bill }`, `null` while no source is attached. `delorun`'s Host attaches the source with `attach(source)`, whose disposer detaches it, and one source is attached at a time ([trust host](../../apps/cli/src/verify/trust-host.ts)). The row asks the source for the start bill once, which the launcher's start check and the stored release-log record make without hashing anything, and then answers the last bill it holds, so the studio's reads never hash. `POST /api/delorunTrust.check` runs the `verify` stage and answers `{ bill }`: the Host runs `delorun verify --json` through the launcher that started it, in a child process, so every runtime file is hashed before the command runs, and runs the stage in its own process, saying so in the bill's `checkedBy`, only when no launcher can be run from there; `checkTimeoutSeconds` (600 by default, 30 to 3600) stops a check that takes longer; concurrent requests share one run, a failure answers `{ error, message }` with `TRUST_SOURCE_MISSING` (503), `TRUST_CHECK_FAILED` (500) or `TRUST_JSON_REQUIRED` (415, a request without a JSON body) and keeps the last bill, and a failed read answers `TRUST_READ_FAILED` (500). A device the home approved may read the bill: the bill route admits a `reach-device` Peer's `GET`. The check route admits no Peer but the owner, so Check now runs only from the studio on the home's own computer. With `enabled` off, the plugin's default, it provides no service and registers no route.
- **工作区重命名工具。**`delorun-workspace-rename` 行挂载 [`@delorun/bundle-local/workspace-rename`](src/workspace-rename.ts)，即 C16 开关 `rename_workspace_tool`，它注册 `rename_workspace` 工具。该工具接收工作区的 id 或当前名称以及新名称，因此 agent 无需手工编辑注册表文件。它先对照上游的工作区注册表检查请求，并在询问之前，以 `WORKSPACE_RENAME_REFUSED` 的措辞拒绝 studio 的重命名所拒绝的情形（名称为空或过长、工作区未知或有歧义、名称已被其他工作区使用）。然后它在调用内通过上游的批准服务询问本人，因此只有 `allowed-once` 才会执行，任何 `tools/pre-execute` 监听器都无法不经询问放行；其他任何回答，或没有批准服务，都以 `WORKSPACE_RENAME_DECLINED` 结束，且不改变任何内容。得到回答之后，它再次检查名称，然后重命名。它返回 `from`、`to` 与 `changed`，用于绘制 studio 的行（`@delorun/plugin-onboarding`）。`headless` profile 不挂载它，因为一次性运行没有人可以回答询问。开关关闭时（插件的默认值），它不注册任何工具。
- **更新闸门。**`delorun-update-gate` 行挂载 [`@delorun/bundle-local/update-gate`](src/update-gate.ts)，即 C16 开关 `update_turn_refusal`，它提供 `delorunTurnGate` 服务。`delorun` 的 Host 以 `attach(isHeld)` 挂接其 chat 闸门的保持状态，其返回的销毁器会解除挂接；只要任一已挂接的来源处于保持状态，插件的 `agent/pre-step` 监听器（先于其他所有监听器运行）就通过抛出 `UpdatePendingError`（错误码 `UPDATE_PENDING`）拒绝每个新轮次的第一步。循环以 `error` 结束该轮次，并带上该错误的消息，其中说明消息未发送，待 Delorun 恢复后请重新发送，且不发出任何模型请求；已在运行的轮次的后续步骤照常进行。开启 `holdUntilChecked` 时，每个轮次的第一步还要等待 `release()`，`delorun` 在其对已启动 Host 的检查通过后调用它，最长等待 `checkWaitSeconds`（1 到 3600 的整数，默认 60）：届时仍在等待的轮次以 `error` 结束，错误为 `StartCheckPendingError`（错误码 `START_CHECK_PENDING`），其消息说明启动时的检查没有完成，请用 `delorun start` 启动 Delorun；第一个等待的轮次会在 Host 日志中以 warn 级别记录一次。开关关闭时（插件的默认值），它不提供服务，也不拒绝任何内容（[C19](../../docs/contracts/c19-home-process.zh.md)）。
- **版本行。**Host 部分把 Delorun 的版本（来自 `delorun` 的 `DELORUN_VERSION`）与上游报告的 DeepSeek Harness 版本，作为全局 `delorunVersions` 打印到每个页面中；浏览器部分校验它，然后以 stock 行的 id `current-version`、排序 -1 注册设置中的版本行，因此它取代该行，只显示“Delorun 版本”。它还注册“通用”行 `delorun-versions`（`VERSIONS_ITEM`，排序 99），只写明 Delorun 的版本，即“Delorun 0.1.0”或“Delorun 源码构建”。DeepSeek Harness 版本在“设置 → 关于”中。不是由 `delorun` 启动的 harness 什么也不打印，因此 stock 行保留，该行不注册。
- **提示服务。**浏览器部分提供 `ctx.delorunNotice`（`acknowledged()`、`acknowledge()`），因此自行显示预览提示文案的流程（例如 `@delorun/plugin-onboarding` 的第一个屏幕）会记录确认，本组合包的提示步骤随之完成，不会再显示第二次。
- **Statements.** The `./statements` export is the Privacy section's English dictionary (`src/client/locales.ts`), which the CLI's setup reads for the statements of its privacy note; the section itself shows the feedback statement only.
- **Delorun 的行来自本次安装。**本组合包的某一行或组合包本身解析到本 Delorun 自身的包（`runtimes/<version>/app` 或源码检出）之外的包时，例如 profile 的 `node_modules` 中同名的包，`delorun` 拒绝启动该 profile（[`compose.ts`](../../apps/cli/src/compose.ts)）。要修改 Delorun 的某个包，请以新名称派生它（例如 `@yourscope/plugin-fetch-guard`），用 `delorun plugin --profile <profile> add <path or spec>` 安装，并让你的 profile 的 `cordis.patch.yml` 中的某一行指向新名称，同时保留 Delorun 的那一行。
- **构建。**`pnpm --filter @delorun/bundle-local run build` 写出 `lib/index.js`（即 `delorun-privacy` 行的 Host 部分）与 `lib/client.js`（即浏览器部分）。上游的 `pnpm run build:artifacts` 不构建 Delorun 的包。

## 行

| 行 | 类型 | 在 Delorun CLI profile 中 | 在上游 web profile 中 | 在对等组合中 |
| --- | --- | --- | --- | --- |
| `plugin-manager` | 已更改 | `config.protectedPlugins` 列出本组合包挂载的同意与守卫插件（其中包括 `@delorun/plugin-changes`）、更新闸门、更新检查、信任账单以及 sandbox 各行的插件：完全访问无需提示即可运行的 `plugin_manager` 工具，既不能禁用这些行、更改它们的设置，也不能取消选择或移除本组合包，因此无法关闭对 agent 的插件安装与移除进行留待审查的那道审查 | 只保护管理器自己的组件 | 上游的组合：overlay 不包含此行，因此 `plugin_manager` 像上游一样列出并拒绝所记录场景的各行 |
| `session-log-deepseek` | 已更改 | `config.enabled: false`：模型请求不带 `dsh_session_log` 字段 | 插件的默认值，`true` | 上游的组合：overlay 不包含此行，因为它遵循每次回放的根配置，该配置按语料设定上传 |

| `product-analytics` | 已更改 | `config.enabled: false`，重述上游的 `appVersion`，并保留上游的 `disabled` 条件，因此该行只在桌面 profile 中挂载，且在那里不接受任何事件 | `config.enabled: true` | 如此处所写；回放不挂载桌面 Host |
| `session-telemetry-otel` | 已更改 | `disabled: true`：没有会话日志前缀随反馈离开本机；上游的反馈导出器会把它发送到 DeepSeek 的收集器 | 启用，`FEEDBACK_ONLY` | 上游的组合：overlay 不包含此行 |

| `ui-account-notifications` | 已更改 | `disabled: true`：账号通知会轮询 DeepSeek 的服务器，获取显示在账号菜单旁的卡片，而 `ui-settings-account` 已将其移除 | 启用 | 上游的组合：overlay 不包含此行 |
| `connection` | 已更改 | `config.oneTimeLaunchTokens: true`（即 C16 开关 `one_time_launch_tokens`），重述 web 组合包的 `trustedHosts` 表达式，并把 `reopenHint` 设为 `run delorun open to open the studio`：每个 studio 登录链接只能在 60 秒内使用一次，且只有 `delorun open` 与启动会生成链接（[C4](../../docs/contracts/c04-admission.zh.md#launch-tokens)） | 在 Host 的整个生命周期内使用同一个可重复使用的启动令牌 | 上游的组合：overlay 不包含此行，因此回放使用可重复使用的令牌登录 |
| `workspace-controller` | 已更改 | `config.defaultWorkspaceDirectory` 是 `!!js process.env.DELORUN_DEFAULT_WORKSPACE`（[`src/profile.ts`](src/profile.ts) 中的 `DEFAULT_WORKSPACE_ENV`），`delorun start` 在启动前于 Host 进程中设置它：当平台查找到的文档文件夹不是 home 目录时为 `<documents>/Delorun/default-workspace`，否则为 `<home>/Delorun/default-workspace`，并且都与 Delorun home、stock home 及临时文件夹保持距离（[`default-workspace.ts`](../../apps/cli/src/default-workspace.ts)）。由其他方式启动时该键保持未设置，因此适用上游的查找；本人可通过在 profile 自己的 `cordis.patch.yml` 中重述该行来选择其他文件夹 | 该行不设置文件夹：首次使用的工作区位于 `<Documents>/deepseek-harness/default-workspace`；平台报告没有文档文件夹时（如没有 XDG Documents 文件夹的 Linux 与 WSL）则没有文件夹 | 上游的组合：overlay 不包含此行，即 C16 存在开关 `default_workspace_directory` 的对等值 |

## PIN mode on a device

A device holds no PIN unlock and sees no PIN lock screen: with PIN mode on, the home refuses `POST /auth/pin/unlock` to every device with `ELEVATION_REQUIRED`, and the studio never sends it. A device confirms each sensitive action with Face ID, or on a device with no passkey with the PIN or passcode typed into the Face ID grant sheet (`src/client/FaceIdPin.tsx`), which posts `/auth/passkey/pin` and mints a grant for that one call. The studio holds no window and no unlock token.

- **The state.** `src/client/pin-lock.ts` reads `GET /auth/pin/state` once at load and after each connection reset, through `src/client/pin-api.ts`, and holds only whether the mode is on and whether it takes a PIN (a digit keypad of at least six digits) or a passcode (a text field). The Face ID sheets read it to choose the keypad. A home with the mode off, an older home (404) and the home's own computer leave the state `off`.
- **Denial tests.** `tests/no-pin-window.client.spec.tsx` fails if the lock screen or a `/auth/pin/unlock` call returns.

## PIN 模式分区

The **PIN mode** section (`delorun-pin-mode`, right after Devices, `src/client/PinModeSection.tsx`) is where the person at the home's own computer turns PIN mode on and off. It reads `GET /auth/pin/mode` and sends `POST /auth/pin/set`, `/off` and `/resume` (`src/client/pin-api.ts`), the computer-only routes of [`@delorun/home-auth`](../home-auth/README.zh.md). It shows whether the mode is on, with a PIN or a passcode, and whether the PIN and Face ID are paused.

- **Turn on.** A PIN or passcode typed twice in masked fields (16 px, so a phone does not zoom); the stored idle minutes and lock-when-hidden go with it unchanged, since no device holds a window for them to end. `src/client/pin-rules.ts` checks the length, repeat, run and common-PIN rules and the match before any request; the home's own check stays the authority and its sentence shows in place.
- **Change PIN.** A separate Change PIN disclosure holds the two secret fields, the same rules and its own Save new PIN button.
- **密码处理。**密码在请求发出之前一直存在于组件的状态中，无论回答如何都会清空，也从不写入存储。
- **Turn off and resume.** Turn off needs no secret but asks one in-place confirmation ("Turn PIN mode off? A phone without Face ID then takes its sensitive actions at your computer."). Resume appears while the PIN and Face ID are paused home-wide after too many wrong tries.
- **在设备上。**该分区显示一行文字，说明 PIN 模式在计算机上设置，并且不发送任何请求。无论如何，home 都会以 `LOOPBACK_REQUIRED` 拒绝设备的请求。

引导流程的“手机访问”步骤用一行文字推荐该模式，并指向这一分区与 `delorun devices pin set`。

The same row carries the studio's surfaces of the two consent plugins it mounts, each over its plugin's routes through same-origin requests (`src/client/consents-api.ts`, over the shared `src/client/host-api.ts`). The copy is in English and Chinese (`src/client/consents-locales.ts`).

- **The full-access consent** (`delorun-full-access-consent`, `src/client/FullAccessConsent.tsx`) is a `shell.overlay` dialog that says in one sentence that the workspace's agents could then run commands outside the sandbox and change files anywhere without asking, and in one that those commands can read the person's keys and tokens; under Details it names the folder and what those commands reach: the person's files outside the workspace, Delorun's home with its keys and tokens, the Docker supervisor and Delorun's update channel, and that it covers that workspace only. Every other switch, and every switch in a workspace that holds a grant, is submitted at once.
- **工作区同意服务。**该行还提供 `ctx.delorunFullAccess.askForWorkspace(path)`，本人为新工作区选择完全访问时由 `@delorun/plugin-new-workspace` 调用：它为该文件夹的工作区显示同一个同意，授权记录后或工作区已有授权时回答 true。主目录未列出的文件夹以及没有按工作区同意的配置不询问，直接回答 false；远程 Studio 显示同意的远程形式，不记录任何内容。
- **The approval card's "Allow for this chat" choice** (`delorun-allow-for-chat` in upstream's `conversation.approval.choice` list slot, [`src/client/AllowForChat.tsx`](src/client/AllowForChat.tsx); the slot is [`@deepseek-ai/dsh-client-ui-approval`](../../../packages/client/ui-approval/README.zh.md)'s) shows in the decision row of a sandbox escalation card, after Reject and Allow once, which then draws as a secondary button. Clicking it switches the chat's permission preset to the mode the request asked for through the same `/permission <preset>` command the composer sends, so the switch is logged and announced to the model as any other, and then answers the card as allowed; later commands in the chat run in that mode without asking until the person lowers it in the composer. A request for workspace write switches at once; a request for full access first shows the one full-access dialog for this chat, which records the workspace's grant when it holds none and switches the chat with it, so no second switch is sent, and cancelling it leaves the card waiting. A chat already at or above the requested mode is not offered the choice, and a remote studio, such as a phone, is not offered it for full access. If the host refuses the switch, the card stays unanswered with the host's sentence under the buttons. Once the card answered, is sending an answer or no longer accepts one, the button is disabled, and a click already under way switches and records nothing more: it reads the card's `canAnswer()` at the click, when the person confirms the dialog and again before the switch.
- **批准卡片的完全访问提示行**（上游 `conversation.approval.action` 列表 slot 中的 `delorun-full-access`，[`src/client/FullAccessAction.tsx`](src/client/FullAccessAction.tsx)）只在远程 studio 上、请求完全访问的卡片中显示：“请在你的计算机上批准。”，因为 home 在那里拒绝工作区审查。在 home 所在的计算机上它什么也不显示。
- **The approval card's Face ID step** (`delorun-face-id-answer` in the `conversation.approval.action` list slot, [`src/client/FaceIdAnswerAction.tsx`](src/client/FaceIdAnswerAction.tsx)) applies to a request that asks for full access, workspace management, an external agent or the real browser, on a remote studio. It sets the card's allow gate, so Allow once, Enter and the other allow choices first open the Face ID action sheet; the grant is minted for exactly the request's Session id, call id and grants marker with the value `allowed-once`, and the answer is sent only after it. A cancelled sheet sends nothing and the card stays answerable; the sheet's way down is the PIN keypad, or Cancel when no PIN is set. Reject, a request that grants nothing or has no call id, and the home's own computer never ask. The same flow serves other plugins through `ctx.delorunFaceGrant` ([`src/client/face-grant.ts`](src/client/face-grant.ts), `FaceIdGrantOverlay.tsx`): a Changes or update control the state says needs Face ID asks for one grant covering exactly its call, and the sheet names the control in its own words (`change.<control>.title` and `.body`).

## The Browser page routes

The `delorun-requirements` row also serves two routes for the Settings Browser page ([`src/browser-check.ts`](src/browser-check.ts)), for the home's own computer only: each is a `POST` that carries no body, admits no paired device, and refuses a request whose `Host` is not a loopback name with `403` and `reason: 'at-computer'` before anything runs. Neither starts a model turn. The studio reads them through [`src/client/browser-check-api.ts`](src/client/browser-check-api.ts), which accepts only a PNG data address of at most 600000 characters as a thumbnail.

- `POST /api/delorunBrowser.test` opens a fixed page that comes with Delorun (no script, no link, no request) in the Browser pack's browser, which starts headless in a fresh profile with the environment of every harness child (`scrubbedParentEnv`), and answers `{ ok: true, image, title }` with a thumbnail, or `{ ok: false, reason, message }` with `not-added`, `not-installed` (the Chromium build is not downloaded), `unreadable` or `failed` and the program's last error line. It stops after 60 seconds.
- `POST /api/delorunBrowser.install` downloads the Chromium build by running `install-browser chromium` of the Playwright MCP package already in the Browser pack, never a package from a registry, and answers `{ ok: true }` or `{ ok: false, reason, message }`. It stops after 15 minutes and runs one download at a time: a second request waits for the one running. A computer that launches its own Chrome, or a row that names an executable, has no download to make and answers `failed`.

<a id="limits"></a>
## 限制

- 组合包列表是供 `delorun` 写入的常量；没有任何已发布的上游模板列出它，因此记录会话回放只通过对等 overlay 挂载本组合包。
- 在 `DELORUN_PROFILE_BUNDLES` 变更之前创建的 profile 保留它创建时的列表。
- 只有 `delorun` 启动的 CLI profile 加载本组合包。`delorun headless` 改为加载 `@delorun/bundle-headless`，它带有同样的同意、抓取防护、轮次闸门以及它们免受插件管理影响的保护，但没有“隐私”分区。
- 隐私默认值只在 profile 加载本组合包时成立。上游会把无法加载的组合包报告为已跳过并在没有它的情况下启动，此时会话日志上传是打开的；`delorun` 拒绝启动这样的 profile，正是这一点保持了这些默认值。
- `delorun` 只把信任账单的来源挂接到它从运行时仓库运行的 Host 上，因此源码检出的 studio 读不到账单，其徽章显示为未知。
- 桌面分析只在上游的 `desktop` profile 中挂载，而 `delorun` 不运行该 profile，因此 Delorun CLI profile 的分区显示该行的原因，而不是开关。
