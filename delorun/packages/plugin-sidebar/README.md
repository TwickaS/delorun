# @delorun/plugin-sidebar

English | [中文](README.zh.md)

## Summary

The chat list of Delorun's studio, in the style of T3 Code's sidebar: chats as cards with a status at each card's top right, the Working, Snoozed and Settled shelves held at the bottom, search, a workspace filter, Workspace folders, Alt jumps, a card of details on hover, workspace icons, generated or T3 Code header art behind the top of the sidebar, and a quiet notice when a newer Delorun release exists. The package registers the list, the art, the foot and the Sidebar section of Settings in upstream's sidebar seats, so upstream's rows, menus and dialogs keep working. The rows, sorting rules, shelves and art are ported from [T3 Code](https://github.com/pingdotgg/t3code) by T3 Tools, under the MIT licence ([notice](THIRD_PARTY_NOTICES.md)); the data is the harness's Sessions and Workspaces. `@delorun/bundle-studio` mounts the package as the row `delorun-sidebar`. It loads only while the Delorun look is on; with the stock look, upstream's list, foot and New Session button return.

## Using it

- **Cards.** Pinned chats come first, in pin order, then the rest with the latest change first (or the latest created, by setting). A card shows its workspace's badge and name, a status (Working with the run's time, Approval, Question, Plan, Done for a finished unread run, Woke for an ended snooze) or the chat's age, its title and its model's mark. Working chats and quiet ready chats recede.
- **Hover and focus.** A card's status gives way to Snooze, Settle and a "..." button; a pinned card shows Unpin. Holding the pointer opens a card of details: the workspace and its folder, the model and the mode. The "..." button, a right-click and the menu key (or Shift+F10) open the chat's menu, which holds every plugin's entries. Double-click or F2 renames; Enter opens. On a screen without hover or with a coarse pointer the status stays and the "..." button sits beside it, with a 32px hit area as the pin and the status button have; the row does not render Snooze and Settle there, and the chat's menu holds them.
- **Shelves.** Working, Snoozed and Settled fold at the bottom with their counts, and each viewer's folding is kept in the browser. A snoozed chat shows its time left and offers Wake now; a settled one offers Return to the list. Settled shows ten chats, then twenty-five more per Show more. A chat waiting on the person or working never sits on the Snoozed or Settled shelf.
- **Dragging**, in the cards view with a mouse or a pen: a card dropped among the pins pins it there, a pinned card dropped below the divider unpins it, a card dropped on Settled settles it, and a settled or snoozed row dropped among the cards returns or wakes it. The dragged row names what the drop does, the list scrolls while the pointer rests near its top or bottom, and Escape cancels. Pins keep the order they are dragged into, kept in the browser. A press that moves less than six pixels is a click. Touch presses scroll the list; every drop is also reachable from the row's buttons and menu.
- **Undo.** Settling, returning, snoozing, waking, pinning and unpinning show what changed and Undo for six seconds, as a small row in the sidebar's foot. It takes no focus and never covers the list.
- **The foot** is one row: a Settings button, the global panels (Plugins, Automation tasks, More) as icon buttons, the undo notice and upstream's other foot actions.
- **Update notice.** When the harness's release check found a newer Delorun release, a small bordered block below the list names it ("Delorun 0.1.3 is available", with "on DeepSeek Harness 0.3.0" when the release moves to another upstream version), the kind of update (security fix, or patch, minor or major release), how many of the person's plugins it would turn off, the release's summary under the label "Release note:", so the release's own text never reads as the studio's instruction, in two lines that a press opens in full, and the command, `delorun update`, to run in a terminal. It applies nothing. A screen reader announces the title and the kind and plugin line; the close button and the summary sit outside that announcement. Its close button, on every page, hides it for that release in that browser only; a newer release shows again. On a page a reach listener served, a remote session such as a phone, the notice is one row, the title ("Delorun 0.1.3") on one line, What's new and the close button at the 44px touch size, and What's new opens the full title, the kind and plugin line, the release note, the release notes button, and the command line that names your computer as the place to run it, unless the Host's update state lets that page begin an update (an unlocked phone at the Full level of Phone powers): then it shows Update now there instead. The notice sits above the sidebar's bottom fade, so no line or button is dimmed or cut. A remote page's close button is a display preference in that page's own storage; it calls no Host route.
- **Search** matches titles and workspaces at once, then the chats' messages through upstream's search; the arrow keys and Enter pick a result. Escape clears a query and keeps the keyboard in the field; with the field empty, Escape is left to the page, so it closes the phone-width drawer, which returns focus to the control that opened it. While the field has the keyboard it shows the studio's focus ring. The shortcut hint goes first when the header is narrow or the pointer is coarse; the label keeps room for "Search".
- **Filter, Add workspace and New chat** sit beside the search field. The filter keeps one or more workspaces, and its submenus change a workspace's icon, rename it or remove it.
- **Alt jumps.** Holding Alt shows 1 to 9 on the first nine visible chats; Alt with a digit opens that chat, read from the physical key so layouts whose Alt types other characters still jump. Nothing happens while a text field or an editable region has the keys.
- **Workspace icons.** Change icon in the filter opens the icon picker: one to three letters, one of 36 icons, an emoji (32 offered, any typed) or a pattern generated from a seed (a mirrored 5 by 5 grid), in the workspace's own colour, one of eight named colours or any colour, a rounded, circle, square or hexagon shape, and a soft, solid or outline style, with Surprise me and Use initials. The chosen icon shows wherever the workspace's badge does.
- **Settings → Sidebar** holds three headed groups. **Header** chooses the header art (none, night sky, blueprint, or one of six generated scenes: waves, aurora, contours, constellation, halftone, shards, each drawn from a seed that Shuffle replaces) as one row of tiles that scrolls sideways with a swipe bar, its palette (Blueprint, Rose, Grove, Ocean, Ember, Iris or the studio's accent), its strength (subtle, standard, vivid), its style (behind the top, or a pill beside the name) and its fade into the sidebar (short, soft, long or none, as tiles previewed on the current scene). **Chat list** chooses the list's style (cards, or Workspace folders with one-line rows and a dot on a folded folder for what waits inside), the sort order (latest change or created), whether working chats gather on their shelf, whether unpinning asks first, and the sidebar's width on a slider from 240 to 420 px with notches at T3 Code's 256 and upstream's 280. Strength, style, list style and sort order are radio groups (`ChoiceGroup` from [`@delorun/settings-controls`](../settings-controls/README.md)): the chosen segment is the one tab stop and the arrow keys move the choice. Each group is a card of the same package: a `<section>` named by its `<h3>` heading over one bordered box. **Collapsed sidebar** has *Expand on hover* (a switch, on by default) and *Hover delay* (a slider from 0 to 1,500 ms in steps of 50, 350 by default, disabled while the switch is off); a change applies at once. The way back to the stock look is Settings → General → Look only.

## Contract

- **Stock look.** The client half injects `delorunStudio` inside `apply` (`ctx.inject(['delorunStudio'], applyStudio)`), so its entry stays active under the stock look, which upstream's web boot requires of every entry. `@delorun/plugin-theme` provides that service only while the Delorun look is on, so without it the plugin registers nothing and changes no layout. Disposing the plugin, or losing `delorunStudio`, removes every registration and restores every `ctx.sidebarLayout` and `ctx.layout` change.
- **The list** fills upstream's `sidebar.workspaces.list` slot with [`src/client/Sidebar.tsx`](src/client/Sidebar.tsx). The slot's owner props give it the Session list, the Workspaces, opening and starting chats, the add-workspace flow, the rename and delete dialogs, message search and `openSessionMenu`, so each chat's menu is upstream's Session menu with every plugin's entries. The list reads `ctx.contextMenus.active` to keep the row whose menu is open lit. While it is mounted, `ctx.sidebarLayout.setNewSessionButton(false)` drops upstream's New Session button from the wide sidebar, `setFootRow(true)` lays the foot out as one row and `setPanelPlacement('footer')` moves the global panels (Plugins, Automation tasks, More) into that row as icon buttons, so the brand sits directly above the list's header. `setHoverPeek` carries `peekOnHover` and `peekDelayMs` to the collapsed rail's hover peek, following changes live.
- **Sorting** is pure, in [`src/client/sections.ts`](src/client/sections.ts): a chat waiting on the person or working never sits on the Snoozed or Settled shelf; otherwise one shelved no earlier than its latest prompt sits there. Subagents, blank chats and archived chats stay out. Auto-settle is derived in the list from the chat states, not stored.
- **Chat states** come from `@delorun/plugin-chat-states` through the optional service `ctx.delorunChatStates`, followed as it comes and goes. Without it the list has no Snoozed or Settled shelves and no Snooze or Settle buttons.
- **Dragging** is [`src/client/drag.ts`](src/client/drag.ts): window pointer events, the row under the pointer found with `document.elementFromPoint`, T3 Code's drop rules from `sections.ts`, and a guard that keeps the click after a drop from opening the row. It uses no library.
- **Update notice.** [`update-notice.ts`](src/client/update-notice.ts) reads `GET api/delorunUpdateCheck.notice` (`UPDATE_NOTICE_PATH` of `@delorun/contract-update-report`, document-relative) when the studio starts, on each `connection/reset`, when the window regains focus or becomes visible, and every `updateNoticeRefreshMinutes`; the answer is validated as `UpdateNoticeResponse` with zod, and a 404 (the check is switched off, so the route is not registered), a failed request or an answer that does not validate is no notice. Only the latest read's answer is shown. The dismissed version is a preference, `delorun:sidebar:update.dismissed` in local storage, held for the page when storage refuses. [`UpdateNotice.tsx`](src/client/UpdateNotice.tsx) renders below the list's scrolling region, so it never covers or moves a row; its `role="status"` region holds only the title and the kind and plugin line, and the close and summary buttons sit outside it; the list passes it `updateNotice` (`UpdateNoticeFace`), whose `dismiss` writes the page's own preference on every page, local or remote (no Host route is called), whose `remote` is true when `ctx.connection.remoteMedia` is `placeholder` (the notice is then one row, and What's new opens the rest), and whose `canOpen` is always true on a local page and, on a remote one, follows the update plugin's `canUpdate` (`may['update-begin']` of its state route), so Update now shows only while it is true and the terminal line shows otherwise. The browser bundle inlines `@delorun/contract-update-report`, `@delorun/contract-release-manifest` and `@delorun/settings-controls` from their sources, since the page's module table does not provide them.
- **The foot.** [`FootLauncher.tsx`](src/client/FootLauncher.tsx) fills upstream's `settings.launcher` seat at priority -2, over upstream's account launcher, with a 32px Settings button. [`UndoNotice.tsx`](src/client/UndoNotice.tsx) fills `sidebar.footer.action` at order -2. The list and the notice share one undo line ([`undo.ts`](src/client/undo.ts)).
- **The art** fills upstream's `sidebar.backdrop` slot with [`StageArt.tsx`](src/client/StageArt.tsx) and [`GenerativeArt.tsx`](src/client/GenerativeArt.tsx). The palettes' literal colours are named `--delorun-art-<palette>-<role>` custom properties with `light-dark()` values in [`art-palettes.css`](src/client/art-palettes.css), the only place the art's literal colours live; [`StageArt.module.css`](src/client/StageArt.module.css) maps a palette's names onto the colours the scenes draw with, and the accent palette mixes `--dsw-alias-brand-primary` with named anchors. Behind the sidebar's top the whole art stays in view, as in T3 Code, and upstream's sidebar draws the brand and the toggle over it in white. The art mounts the edge's SVG filters (`InkEdgeFilters`) under the ids upstream draws them through (`INK_EDGE_IDS`): each grows the ink's shape by `INK_EDGE_RADIUS` and fills the growth in a static near-black (`INK_EDGE_TOKEN`) at `INK_EDGE_OPACITY` of the ink's own opacity, over a soft shade (`INK_EDGE_SHADE`), and draws the ink on top. Against its own edge over every colour any scene draws in, the title reads at 4.5:1 and the toggle at 3:1 or more; a solid plate or a band of the sidebar's fill under the row would hide the art the setting chose. The Settings tiles' brand draws through filters the section mounts under its own ids. The pill style and no art mount no filters and leave the title on the sidebar. The generated scenes draw with a seeded mulberry32 source in the palette's `--stage-art-*` colours. The pill style marks itself `data-backdrop-plain` so the brand keeps its colours.
- **Workspace icons** are stored data. The `workspaceIcons` setting accepts any value so one bad icon cannot keep the row from loading; the list validates each icon where it reads it ([`readWorkspaceIcons`](src/workspace-icon.ts)), and a workspace whose stored icon is malformed, such as one naming an icon the picker no longer offers, shows its monogram. The setting holds at most `MAX_WORKSPACE_ICONS` (200) entries: the host half refuses to load a row whose stored value holds more, with a `RangeError`, since the schema itself carries no transform the studio could not rehydrate; saving an icon makes it the newest entry and drops the oldest beyond the bound (`withWorkspaceIcon`), and once the Workspace list has loaded, the list drops the icons of workspaces that no longer exist (`pruneWorkspaceIcons`), never while the list is still loading. The glyphs are upstream's `Icon*Medium` components, chosen in [`WorkspaceBadge.tsx`](src/client/WorkspaceBadge.tsx).
- **Settings.** The width reaches `ctx.layout.setSidebarWidths` while that service exists, with the drag floor at 264 px or the width when narrower. The Sidebar section ([`SettingsSection.tsx`](src/client/SettingsSection.tsx)) has the id `delorun-sidebar` and order 2, registers only while the Host serves the `delorun-sidebar` settings namespace, writes through `ctx.configForms` and shows a notice when a write fails. The harness half asks the settings service for no generated form for the namespace. The section has no stock-look button.
- **Styling.** Spacing is `--delorun-space-1` to `--delorun-space-9`, type sizes are `--dsw-font-*`, corners and colours are the studio's tokens, so the list follows the theme; the lengths T3 Code specifies (16px status icons, 36px slim rows, 32px foot buttons) are named custom properties declared once at the top of each stylesheet, and the badge's colours are named in [`badge-colors.css`](src/client/badge-colors.css). Text is set in the primary or secondary label and no heavier than weight 500. Hover-only styling is inside `@media (hover: hover)`, transitions and animations inside `@media (prefers-reduced-motion: no-preference)`; coarse pointers get 32px hit areas. [`styles.spec.ts`](tests/styles.spec.ts) checks these rules on the stylesheets' text.
- **Add workspace offer.** While the list is mounted, `ctx.delorunSidebar` (`DelorunSidebar`) offers `canAddWorkspace()` and `addWorkspace()`, backed by the latest `canAddWorkspace` and `addWorkspace` owner props of `sidebar.workspaces.list`; it is withdrawn when the list unmounts or the Delorun look leaves.
- **Exports.** `@delorun/plugin-sidebar/client` exports `apply`, `inject`, `NS`, `SECTION`, `LAUNCHER_PRIORITY`, `UNDO_NOTICE`, `DelorunSidebar`, the brand row's edge (`InkEdgeFilters`, `INK_EDGE_IDS`, `INK_EDGE_OPACITY`, `INK_EDGE_RADIUS`, `INK_EDGE_SHADE`, `INK_EDGE_TOKEN`, `InkEdgePart`), the row and list types, `createUndoLine`, the update notice (`UpdateNoticeStore`, `UpdateNoticeResponseSchema`, `fetchUpdateNotice`, `DISMISSED_KEY`, `UpdateNoticeCard`), `useListDrag`, the art, badge and picker components, the pure functions of `sections.ts` and `workspace-icon.ts`, and the helpers `optionalSource`, `snoozeEnds` and `stateActions`. `@delorun/plugin-sidebar` exports `apply`, `Config`, `MAX_WORKSPACE_ICONS`, `UPDATE_NOTICE_REFRESH_MINUTES`, the setting types and the icon schema.
- **Copy** is in English and Chinese ([`src/client/locales.ts`](src/client/locales.ts)); the Plugins page names the row from [`locale/`](locale/en.json).

## Configuration

The row `delorun-sidebar` has twelve volatile fields ([`src/config.ts`](src/config.ts)), validated when the configuration loads and changeable while the studio runs. Settings → Sidebar edits them, except that Shuffle replaces `artSeed`, the icon picker edits `workspaceIcons`, and `updateNoticeRefreshMinutes` is set in `cordis.yml` only.

| Field | Default | Meaning |
| --- | --- | --- |
| `headerArt` | `blueprint` | `none`, `night`, `blueprint`, `waves`, `aurora`, `contours`, `constellation`, `halftone` or `shards`. |
| `artPalette` | `accent` | `blueprint`, `rose`, `grove`, `ocean`, `ember`, `iris` or `accent`. |
| `view` | `cards` | `cards`, or `folders` for a folder per workspace. |
| `workingShelf` | `true` | Whether working chats gather on the Working shelf. |
| `artSeed` | `1` | The seed (1 to 2,147,483,647) a generated scene is drawn from. |
| `artStrength` | `standard` | `subtle`, `standard` or `vivid`. |
| `artFade` | `soft` | `short`, `soft` (T3 Code's), `long` or `none` (a hairline in the border colour). |
| `artStyle` | `artwork` | `artwork` behind the sidebar's top, or `pill` beside the brand. |
| `sort` | `updated` | `updated` (latest change) or `created`. |
| `confirmUnpin` | `false` | Whether unpinning asks first, from the button or a drag. |
| `width` | `256` | The sidebar's width in pixels, 240 to 420 in steps of 4. |
| `peekOnHover` | `true` | Whether resting the pointer on the collapsed rail shows the full sidebar over the page. |
| `peekDelayMs` | `350` | Milliseconds the pointer rests on the rail before the sidebar expands, 0 to 1500 in steps of 50. |
| `workspaceIcons` | `{}` | Each workspace's icon by workspace id, at most 200, oldest first; invalid entries are ignored when read. |
| `updateNoticeRefreshMinutes` | `60` | Minutes between the studio's reads of the update notice, 5 to 1440 whole minutes. |

## Limits

- The pins' order is per browser: the harness keeps no order of its own for pinned chats, so a dragged order shows only where it was dragged.
- The list shows no git branch for a workspace and the foot has no cell status, Usage or update button, because no browser service provides them in this studio; the update notice names the command and applies nothing.
- Dragging works with a mouse or a pen. Touch and keyboard use the row's buttons and menu for the same operations.
- T3 Code's archive and delete confirmations are not repeated: upstream's archive notice offers Undo, and deleting a workspace always asks.
- The folded rail keeps upstream's list. The list is a child seat of upstream's browsing region, so a plugin that occupies that region at a lower priority replaces the list with it; upstream's sidebar reserves the region against that, refusing a registration below priority 0 and naming `sidebar.sections`, the additive seat beside the list.

## Tests

`node_modules/.bin/vitest run --config delorun/vitest.config.ts packages/plugin-sidebar/` runs the specs; [`sidebar.spec.ts`](tests/sidebar.spec.ts) imports upstream's built packages, so it needs `pnpm run build:artifacts`. The client specs resolve upstream to its sources.

- [`sections.client.spec.ts`](tests/sections.client.spec.ts) checks statuses, receding, which chats are listed, the sections and shelves (a chat that waits or works is never shelved), search, the filter, badges, folders, auto-settle and the drop rules, verbs and the pins' order.
- [`workspace-icon.client.spec.tsx`](tests/workspace-icon.client.spec.tsx) checks the icon schema, that a malformed stored icon is left out when icons are read, the random icon, the seeded pattern, and the bound and pruning of the stored icons.
- [`title-contrast.client.spec.tsx`](tests/title-contrast.client.spec.tsx) measures the title's and the toggle's white ink, read from upstream's light rule and drawn over its edge at the share, against that edge composited over every named art colour and accent mix at each strength and over the sidebar's fill, for every theme palette and colour scheme, importing the theme's palette generator from its source; it fails when the title reads under 4.5:1 or the toggle under 3:1, when an edge is more than four points heavier than the lightest that reads, without an edge, or with the toggle at the title's share. It checks that upstream draws the brand and the toggle's icon through `INK_EDGE_IDS`, the filters' drawing, that every art behind the sidebar's top mounts them unmarked, and that no art and the pill mount none.
- [`styles.spec.ts`](tests/styles.spec.ts) reads the stylesheets and checks literal colours, weights, lengths, hover, motion, text roles, the coarse-pointer hit areas, and the search field's narrowing and focus ring, and the weight that sets the update notice's "Release note:" label apart.
- [`sidebar.client.spec.tsx`](tests/sidebar.client.spec.tsx) checks the update notice's place below the scrolling region, the cards and shelves, a shelf's folding kept, settling, snoozing, waking and unpinning with Undo, the chat's menu from its button, a right-click and the menu key, opening and renaming, the list without chat states, the Working shelf off, the filter and the icon picker, search by title and by message, Escape in the search field (a query cleared with the keyboard kept, an empty field leaving Escape to the phone-width drawer, which closes and returns focus to its opener), the folders view, Alt jumps (not while typing), every drop, the row on a touch screen, the pruning of removed workspaces' icons and the add-workspace offer.
- [`drag.client.spec.tsx`](tests/drag.client.spec.tsx) checks the six-pixel threshold, the drop target, Escape and cancel, the touch and button exclusions, the click guard and the edge scrolling.
- [`icons.client.spec.tsx`](tests/icons.client.spec.tsx) checks the badge for each kind of icon and the picker.
- [`art.client.spec.tsx`](tests/art.client.spec.tsx) checks every scene and palette, the seeded scenes, and the pill style.
- [`settings-section.client.spec.tsx`](tests/settings-section.client.spec.tsx) checks each setting's write, the width slider, the Collapsed sidebar rows (the delay muted and disabled while Expand on hover is off), the swipe strip, a failed write, the read-only state, and that the tiles' brand draws through the section's own edge filter over art.
- [`update-notice.client.spec.tsx`](tests/update-notice.client.spec.tsx) checks that `null`, a 404, a failed request and each kind of invalid answer read as no notice, the notice's text for a security fix, a minor release with a base move and a summary, and the plugin counts, a live region that holds no control, the summary's "Release note:" label in English and Chinese, dismissal per release and its storage (including storage that refuses), that a remote session's notice has the close button, which hides it for that release, and that it is one row until What's new opens the kind line, the release note, the release notes button and the terminal line, while the computer's page keeps What's new below, and the reads on start, reset, focus, visibility and the interval, the latest answer winning and the disposal.
- [`plugin.client.spec.tsx`](tests/plugin.client.spec.tsx) checks the registrations and their removal, the update notice's reads, dismissal and remote session through the studio half, that the plugin registers nothing and changes no layout without the Delorun look, the optional chat-states service, the foot, `ctx.delorunSidebar`, the bound on saved icons, and that the copy follows the glossary and has every English key.
- [`sidebar.spec.ts`](tests/sidebar.spec.ts) checks the `Config` defaults and refusals, that the schema serialised and rehydrated as the studio's settings form rebuilds it still validates a stored value, the bound on Workspace icons at load, and the host half.
- `apps/web/tests/delorun-update-notice.e2e.ts` builds Delorun's studio packages, attaches a fixed check to the Host's `delorunUpdateCheck` service so the real route serves its notice, skips the onboarding dialog that covers the sidebar in a fresh profile, and checks in Chromium the notice's text and live region, that its close button hides it, and that a remote session's page has a close button that hides the notice.
