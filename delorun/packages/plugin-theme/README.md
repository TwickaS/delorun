# @delorun/plugin-theme

English | [中文](README.zh.md)

## Summary

`@delorun/plugin-theme` owns C16 switch `studio_additions`. While the switch is on it lays Delorun's Soft palette, an accent and Delorun's typefaces over upstream's theme tokens, adds the Appearance and Conversation sections and four General rows to Settings, sets Delorun's New Session headline and vocabulary, and provides the `delorunStudio` browser service, which every other Delorun studio plugin requires. Turning the switch off unloads all of them, and the studio is upstream's. The plugin then registers one General row (`settings.general.item`, id `delorun-look`) that turns the switch on again.

## Contract

- **The switch.** The `studioAdditions` setting is a live-editable boolean in the `delorun-theme` row's `Config` ([`THEME_ROW_ID`](src/config.ts)). Its default is `false`, which is the parity value: a profile that mounts the row without setting it gets upstream's look. `@delorun/bundle-studio`'s row sets it `true`, which is Delorun's default composition ([C16](../../docs/contracts/c16-parity-composition.md)). The switch changes what a person sees and reaches nothing the model reads.
- **`ctx.delorunStudio`.** `@delorun/plugin-theme/client` merges `delorunStudio: DelorunStudio` into the browser `Context`. The service exists exactly while the stored switch is on and is withdrawn when it is off. A Delorun studio plugin registers everything inside `ctx.inject(['delorunStudio'], …)`, so the stock look disposes its registrations while its entry stays active; a top-level `inject` entry would leave the entry pending, which upstream's web boot reports as a failed start. `DelorunStudio.useStockLook(): Promise<boolean>` writes `studioAdditions: false` through upstream's configuration form and returns whether the Host accepted the write.
- **Before the Host answers.** Until the settings form first answers, the plugin follows the settings the host half printed into the page (`delorunThemeSettings`, [`src/boot-settings.ts`](src/boot-settings.ts)), so on a page served with Delorun's look the look, the sections and `ctx.delorunStudio` are in place while the studio boots, and every Delorun studio plugin registers before the studio first renders instead of after the stock sidebar has shown. The form's first answer replaces them: the stock look if the switch was turned off after the page was served, nothing when the Host does not serve the row. A page served with the stock look carries no settings, and printed settings that do not validate are reported with a console warning; in both cases the plugin registers nothing and provides no service until the form answers, and it releases everything when the form later reloads.
- **Exports.** `@delorun/plugin-theme/client` exports `THEME_ROW_ID` (`'delorun-theme'`), `ThemeSettings` with the choice lists and types (`ACCENT_CHOICES`, `PALETTES`, `TYPEFACES`, `DENSITIES`, `EFFORT_DISPLAYS`, `DEFAULT_SETTINGS`), `DelorunStudio`, the section and row ids (`SECTION_ID`, `CONVERSATION.id`, `LOOK_ROW.id`, `STUDIO_ROWS`) with their orders, `STOCK_ATTRIBUTE` and `ThemeController`. A package that offers the look choice elsewhere, such as onboarding, writes the `studioAdditions` field of `THEME_ROW_ID` through `ctx.configForms`.
- **Branding.** The `branding` setting of the theme row holds the person's own branding: show or hide the mark, a name, an icon (the Delorun mark, a picked workspace icon, or an uploaded PNG, JPEG or WebP of up to 256 KB) and a greeting. [`@delorun/brand/branding`](../brand/src/branding.ts) validates every field wherever it is read: the browser (the Branding block of the Appearance section, the hero, the sidebar header, the tab title and favicon), the host's fixed icon route `/delorun/branding/icon`, and `@delorun/home-auth`, which reads the same settings row to brand its sign-in and pairing pages. A record that does not validate shows the Delorun defaults and a notice in the block. An uploaded image is stored once, as `storages/delorun-theme/branding-icon` under the home, which an update's session-data copy already includes; the row holds only its SHA-256 hash. A `POST` to the icon route checks the bytes on the host (PNG, JPEG or WebP by their first bytes, at most 256 KB, never SVG), writes the file atomically and answers the hash; an approved device may post it as it writes any everyday setting. The `GET` serves the file only when it hashes to the row's hash, so a replaced or missing file shows the default. A row from before the file store, which holds the image as base64, still reads and moves to the file on its next save; resetting the profile leaves a hash that matches no file, which shows the default. The host prints the record without any upload into the page. A picked icon is drawn from the shipped glyph set by id (`@delorun/brand/picked-icon`) on the sign-in pages and the tab icon, and through the components `@delorun/plugin-sidebar` shares as `ctx.delorunSidebar` in the studio.
- **Host half.** [`src/index.ts`](src/index.ts) stores the settings and tells the settings service to build no automatic form for the row, because the Appearance section and the General rows edit it. While the switch is on it prints the palette, accent, density and contrast as a `style` row through `webserver/index-inject`, so the first paint is already Delorun's look, a `global` row `dshBootWordmark` = `Delorun` (`BOOT_WORDMARK_GLOBAL`, `BOOT_WORDMARK`), which upstream's boot page reads as its wordmark, and a `global` row `delorunThemeSettings` (`BOOT_SETTINGS_GLOBAL`) holding the current settings, which the browser half follows until its settings form answers. While it is off the host prints none of them.

## Configuration

| Field | Values | Default | Effect |
| --- | --- | --- | --- |
| `studioAdditions` | boolean | `false` | C16 switch `studio_additions`: on, Delorun's look and every Delorun studio plugin; off, upstream's stock look. |
| `palette` | `soft`, `t3-code`, `t3-chat`, `grove`, `ocean`, `ember`, `iris`, `custom` | `soft` | The palette. The first seven are presets that fix their own colours and accent: Soft, Slate (`t3-code`), Berry (`t3-chat`), Grove, Ocean, Ember and Iris. `custom` is Soft's surfaces with the accent and contrast below. The two ids keep the names a saved choice was stored under. Settings stored with a preset beside a changed accent or contrast read as `custom` ([`lookOf`](src/palette/migrate.ts)): Soft keeps its accent and contrast, and a T3 Code preset with a changed contrast keeps only its accent colour. |
| `accent` | `peach`, `cobalt`, `moss`, `mono`, `custom` | `peach` | The accent of primary buttons, links, switches and focus, read only with the `custom` palette. |
| `customAccent` | `#RRGGBB` | `#E5734A` | The colour used when `accent` is `custom`. |
| `typeface` | `delorun`, `system` | `delorun` | Schibsted Grotesk and JetBrains Mono, or upstream's stacks. |
| `density` | `compact`, `comfortable`, `spacious` | `comfortable` | `--dsh-density`, the scale spacing rules multiply by: 0.8, 1 and 1.2. |
| `contrast` | 50 to 200, step 5 | `100` | Quiet text and rules move towards the page below 100 and towards primary text above it. |
| `effort` | `label`, `bars` | `label` | How the model picker shows reasoning effort. |

Every field is volatile, so the Appearance section and the General rows edit it while the studio runs.

## The look

While the switch is on, the browser half ([`src/client/index.ts`](src/client/index.ts)) registers, and releases when the switch turns off or the plugin is disposed:

- **Token layers** through `ctx.theme.overrideTokens`, one source per layer: palette, accent, type, density and contrast ([`LAYERS`](src/client/controller.ts)). Colours are OKLCH seeds that generate both schemes from upstream's token sheet; the accent is a separate layer, and each text role gets a text-safe shade that reaches 4.5:1 on its surface. The palette also darkens or lightens the secondary and tertiary label roles until each reaches 4.5:1 on every opaque background role ([`TEXT_SURFACES`](src/palette/soft.ts)) at the default accent and contrast, in both schemes. The density layer also defines the spacing tokens `--delorun-space-1` to `--delorun-space-9` (2, 4, 6, 8, 12, 16, 20, 24 and 32 px), each multiplied by `var(--dsh-density, 1)`, which exist only while the look is on. Light, dark and system stay upstream's preference.
- **Faces and effort bars** as one `<style data-plugin="@delorun/plugin-theme">` element: the two Latin font files that `scripts/copy-brand-fonts.ts` copies from `@delorun/brand` into `src/client/assets/fonts` at build time, and the rules that draw the model picker's `data-effort-level` caption as bars while `effort` is `bars`. The same element holds the composer's focus ring and the panel toggles' glyphs (`src/client/panel-glyphs.ts`): upstream draws the sidebar and side panel toggles with one panel icon, so a CSS mask over `[data-sidebar-opener]`, `[data-sidebar-toggle]`, `[data-sidebar-right-expand]` and `[data-sidebar-right-toggle]` paints the sidebar with list lines in its column and the side panel with a shaded right-hand column, in `currentColor`, while names, tooltips and shortcuts stay upstream's; under forced colours upstream's icon shows.
- **Settings sections.** Each section draws its own `<h3>` card headings, styled by the Settings panel's `--dsh-settings-card-heading-*` variables, so it reads the same with or without the grouped Settings layout. `delorun-appearance` (order 1) is two cards: "Colours" (the colour scheme as one segmented row, the themes as a grid of tiles ending in Custom, and a compact live sample; the accent and the contrast show inline only while Custom is chosen) and "Branding" (`BrandingSection`, rendered by the section with its own dictionary `settings.delorunBranding`). `delorun-conversation` (order 2) edits upstream's `ui-chat` display settings in two cards: "Detail" (the display presets with a live preview, thinking as a select, step grouping, live detail and terminal output) and "Folding" (fold finished turns, when to fold and which replies stay). It appears only while the Host serves that namespace.
- **General rows** (`settings.general.item`, on the Appearance dictionary), each writing one field of this plugin's settings ([`STUDIO_ROWS`](src/client/index.ts)):

  | Id | Order | Title | Control | Writes |
  | --- | --- | --- | --- | --- |
  | `delorun-look` | 1 | Delorun look | An on switch | Turning it off writes `studioAdditions: false` through `useStockLook()` |
  | `delorun-typeface` | 10.5 | Typeface | tiles with a specimen | `typeface` |
  | `delorun-density` | 11.5 | Density | tiles with rows at each spacing | `density` |
  | `delorun-effort-labels` | 20.5 | Reasoning effort labels | Name / Bars | `effort` |

  The orders place them among upstream's rows when no layout places them: Typeface between the colour scheme (10) and font size (11), Density after font size, Reasoning effort labels after the composer's Enter behaviour (20). `delorun-look` is the stock look's row id too; the two are never registered together.
- **The New Session hero.** The text wordmark (`hero.mark`, "Delorun", in the brand dictionary) in `conversation.hero.brand.mark`, at least as wide and as high as upstream's mark for the requested size so the headline keeps its place, and the headline in `conversation.hero.headline`. The brand mark in the sidebar belongs to `@delorun/bundle-local`.
- **The vocabulary.** One `ctx.locale.override` per namespace and locale of [`src/client/vocabulary.ts`](src/client/vocabulary.ts), which says "chat" where upstream says "session", then the hand-written fixes of [`src/client/copy.ts`](src/client/copy.ts), in English and Chinese. `scripts/gen-vocabulary.ts` writes the first file from upstream's dictionaries.
- **`ctx.delorunStudio`**, provided for the same span.

The CSS of the sections and rows uses upstream's tokens (`--dsw-alias-*`, `--dsw-radius-*`, `--dsw-font-*`) and the spacing tokens; geometry that is neither is a named custom property declared once per section or row, weights stop at 500 except the card heading, whose weight is the Settings panel's variable, transitions run only under `prefers-reduced-motion: no-preference`, and palette seeds are data in TypeScript. The cards, row frames, radio groups and preview tiles come from [`@delorun/settings-controls`](../settings-controls/README.md): two or three short options are radio groups (`ChoiceGroup`), one tab stop, arrow keys move the choice; options that need a picture are preview tiles (`TileGroup`); and the five thinking displays are a select, upstream's `Menu` behind a button. The sections reflow at phone width: tiles keep their rows and shrink, and every other row wraps.

## The Plugins screen

While the look is on, the style element also carries two sets of rules for upstream's Plugins screen, and the plugin overrides one word of that screen's copy. The stock look removes all three, so upstream's screen returns.

- **The Experimental plugins control.** Upstream draws the group's More action as a quiet text link beside the heading, so a person cannot tell it is a control or how many plugins sit behind it. [`src/client/experimental-more.ts`](src/client/experimental-more.ts) gives it the secondary button's shape — upstream's own outline hairline, `--dsw-radius-sm` and the spacing tokens — and states the count the page carries in `data-plugin-more-count` through `attr()`, so nothing is read from the Host and no observer runs. The count is a pseudo-element, which the accessible name computation includes, so a screen reader says "Show experimental · 11" once; the chevron takes `order: 1` so the count sits between the words and the chevron. A page that sets no attribute, such as an older upstream, matches no count rule and shows neither a separator nor a count. The label itself is the `moreAction` override of the `pluginManager` namespace, "Show experimental" in English and "显示实验性插件" in Chinese.
- **The on-demand rows.** Codex subagent and Claude Code subagent are the release's `ON_DEMAND_BUNDLES`: they install when a person adds them, so the Host reports them as absent from the profile with the plugin manager's signed-pack refusal, and the page draws that as a red "Problem" tag. [`src/client/on-demand-rows.ts`](src/client/on-demand-rows.ts) hides that tag on those two rows and their pages and states "Installs on demand" beside the title instead, in the words [`src/client/on-demand-label.ts`](src/client/on-demand-label.ts) sets in `--delorun-on-demand-label` from the `delorunPluginList` dictionary and keeps current as the language changes. The tag is hidden only while the row also carries the page's "Not installed" tag, so a bundle that is installed and genuinely broken keeps its red tag. The row keeps the page's own "Not installed" tag and the Add action `@delorun/plugin-downloads` draws for a pack that is not in the home. The names come from upstream's own list, so a bundle that joins or leaves it needs no change here.
- **The surfaces the rules reach** are upstream's stable ones: `data-plugin-group="extensions"`, `data-plugin-package`, `data-plugin-detail`, and the `.groupMore`, `.statusTag` and `.titleRow` classes, which CSS Modules hash and the rules match by the suffix they keep.

## Alerts and pop-ups

While the look is on, the style element also carries [`src/client/alerts.css`](src/client/alerts.css), the one quiet glass style of every alert and pop-up in the studio. The stock look removes it with the rest of the element, so upstream's toast and dialog keep upstream's styles.

- **Surface tokens** on `body`, which follow the scheme: `--delorun-glass-fill` (`--dsw-alias-bg-layer-1` at 86% opacity), `--delorun-glass-fill-solid`, `--delorun-glass-blur` (a 24 px backdrop blur), `--delorun-glass-edge` (a 1 px `--dsw-alias-border-l2` hairline), `--delorun-glass-shadow` and `--delorun-glass-shadow-raised` (a contact shadow under a soft drop, stronger in dark, where a 1 px top highlight is added), `--delorun-glass-radius` (`--dsw-radius-md`) and `--delorun-glass-radius-dialog` (`--dsw-radius-lg`). The surface is opaque where `backdrop-filter` is unsupported, under `prefers-reduced-transparency: reduce` and under `prefers-contrast: more`, which also takes the stronger `--dsw-alias-border-l4` edge.
- **The alert** is [`@delorun/brand`'s `Alert`](../brand/README.md): a 24 px tinted circle with a 14 px glyph of its own for each kind (info, success, warning, error, progress), a 14 px title at weight 500, one 13 px line in `--dsw-alias-label-secondary`, a tinted text button (`--delorun-alert-action`, the accent's text colour mixed 80% with the primary text, on 8% of the accent, 12% in dark), a quiet button and an optional close. Its variants are `inline` (a column such as the sidebar), `toast` (at most 380 px) and `banner` (actions on the text's row). A dialog uses `delorun-glass` with `data-variant="dialog"` (440 px, 24 px padding) and puts its actions in `delorun-alert-dialog-actions`, secondary first and primary last.
- **Motion:** an 8 px slide and fade in over 200 ms (`--delorun-alert-ease`, a soft ease-out) and out over 150 ms, as transitions on `transform` and `opacity`, so a leave that starts mid-enter turns back from where the card is. Under `prefers-reduced-motion: reduce` nothing slides or fades, and the progress glyph stops turning.
- **Upstream's surfaces,** through stable attributes and without edits: the toast (`[data-toast-area] > [role='alert']`) becomes the glass card, with its glyph in a tinted circle and its action in the action colour, and it enters and leaves by the same slide toward the toast position the person chose; the dialog (`[role='presentation'] > [role='dialog'][aria-modal='true']`, so also `@delorun/brand`'s `Dialog`) takes the glass at dialog size and the same enter.
- **Contrast:** the title, the line and the tinted action reach 4.5:1 on the glass in every preset palette and both schemes, over a page covered in dense text under the blur ([`alerts.client.spec.ts`](tests/alerts.client.spec.ts)).

## The stock look

While the switch is off, nothing of Delorun's look applies: no token layer, no font faces, no style element, no first-paint style, no sections, no headline, no vocabulary and no service. The plugin registers one row in `settings.general.item` (`delorun-look`, after Language) with a switch labelled "Delorun look" and a one-line description; turning it on writes `studioAdditions: true`, and the studio comes up without a reload. It also sets `data-delorun-stock` on `<html>` and removes the first-paint style element the page was served with (found by `FIRST_PAINT_MARK`, the start of its text), so upstream's colours return at once. Disposing the browser half removes that element too. The studio half's Look row is the same switch from the other side: it is on, and turning it off calls `useStockLook()`.

Soft is Delorun's. T3 Code's six themes are seeded from [`src/palette/t3-themes.ts`](src/palette/t3-themes.ts), copied by [`scripts/sync-t3-themes.ts`](scripts/sync-t3-themes.ts) from T3 Code (MIT, © 2026 T3 Tools Inc.) at a recorded commit; [`src/palette/t3.ts`](src/palette/t3.ts) derives each palette from it: the tint of its greys, the lightness of its light page and sidebar, and its accent in both schemes. The licence texts and the T3 Code notice are in [`THIRD_PARTY_NOTICES.md`](THIRD_PARTY_NOTICES.md) and [`fonts/`](fonts), and the package publishes both.

## Tests

`node_modules/.bin/vitest run --config delorun/vitest.config.ts delorun/packages/plugin-theme` runs the package's specs. The `.spec.ts` specs import upstream's built packages and need `pnpm run build:artifacts`; the `.spec.tsx` specs run in jsdom against upstream's sources.

- [`palette.spec.ts`](tests/palette.spec.ts) holds the generated palettes to upstream's token sheet and to WCAG: body text roles reach 4.5:1 on their surfaces and marks 3:1, for Soft with each preset accent and edge-case custom accents, and for each T3 Code theme, in both schemes; secondary and tertiary label roles reach 4.5:1 on every opaque background role for every palette in both schemes. It also covers the spacing tokens, the contrast setting, the first-paint style and the colour arithmetic.
- [`t3.spec.ts`](tests/t3.spec.ts) and [`t3-broken.spec.ts`](tests/t3-broken.spec.ts) cover the T3 Code source parser, the shipped themes and the refusals of a theme file that lacks a role.
- [`vocabulary.spec.ts`](tests/vocabulary.spec.ts) fails when the committed vocabulary differs from what the generator writes from upstream's dictionaries, and checks the hand-written fixes and the attributes the effort bars read.
- **The main landmark.** While the Delorun look is on, [`src/client/landmark.ts`](src/client/landmark.ts) marks upstream's main pane (`data-slot="main"`, a plain `div` in upstream's frame) `role="main"`, again whenever the frame renders the pane anew, and takes the role off with the look. A pane that already has a role is left alone.
- [`host.spec.ts`](tests/host.spec.ts) checks the settings defaults, that `studioAdditions` is volatile with default `false`, and that the first-paint style, the boot wordmark and the settings are printed only while the switch is on.
- [`landmark.client.spec.tsx`](tests/landmark.client.spec.tsx) checks that the main pane is marked when it is present, when it appears later and when the frame replaces it, that a pane with a role is left alone, and that disposing removes the role and stops the watch.
- [`boot-settings.client.spec.tsx`](tests/boot-settings.client.spec.tsx) reads printed settings back and refuses a value with a missing field or a field the configuration does not accept.
- [`alerts.client.spec.ts`](tests/alerts.client.spec.ts) holds the alert sheet to the `Alert` component's classes, the opaque fallbacks, transform-and-opacity motion that stops under reduced motion, and AA contrast on the glass.
- [`studio.client.spec.tsx`](tests/studio.client.spec.tsx) proves the switch: off, there is no service, layer, style element, face, section or vocabulary, and only the General row is registered, and the alert sheet leaves with the style element; on, the service, the look, the hero wordmark and the four General rows are present, and the rows write through the theme row's form, and the first-paint element is gone after the look leaves or the plugin is disposed; `useStockLook()` unloads a dependent plugin; without printed settings nothing is registered before the Host answers; with them the look and the service, and so a dependent plugin, are in place while the form loads, the form's first answer replaces them, and invalid printed settings are reported and ignored.
- [`appearance.client.spec.tsx`](tests/appearance.client.spec.tsx), [`appearance-rows.client.spec.tsx`](tests/appearance-rows.client.spec.tsx), [`conversation.client.spec.tsx`](tests/conversation.client.spec.tsx), [`look-row.client.spec.tsx`](tests/look-row.client.spec.tsx) and [`controller.client.spec.tsx`](tests/controller.client.spec.tsx) render the sections, the rows and the controller: each control writes its field, the headings name their sections, and the Thinking select opens a menu of the offered displays. `tests/panel-glyphs.client.spec.tsx` checks that the glyph rules reach the icon of each of the four panel toggles and no other use of that icon, paint in `currentColor` outside forced colours, and are removed with the stock look. [`experimental-more.client.spec.tsx`](tests/experimental-more.client.spec.tsx) checks that the More control's rules reach the Experimental plugins group's control and no other button, give it the secondary button's shape, state the count only where the page sets the attribute, put the count before the chevron, and leave with the stock look. [`on-demand-rows.client.spec.tsx`](tests/on-demand-rows.client.spec.tsx) checks that the rules reach every on-demand bundle the release lists on its row and its page, hide the red tag only under the page's "Not installed" tag, state the wording, leave a bundle that is not on demand alone, set the wording as a quoted custom property that follows a change of language, and leave with the stock look.

## Limits

- The browser half cannot import another Delorun package at run time, because the page's module table provides upstream's packages only.
- This plugin registers no sidebar brand.
- Turning the switch off does not reload the page; the first-paint style element is removed and `data-delorun-stock` on `<html>` keeps any copy from applying.
- The boot page shows the wordmark only on a page served after the host printed `dshBootWordmark`.

## Shared controls and Safari edges

The chip controls (`ChipGroup`, `ThemePicker`, `AccentPicker`) and the `StudioLookSwitch` that Settings → Appearance and onboarding's Look step share live in [`@delorun/brand`](../brand/README.md), the one control set; [`src/client/controls`](src/client/controls) only re-exports them as `@delorun/plugin-theme/controls`. [`src/client/edges.ts`](src/client/edges.ts) paints two fixed, `aria-hidden` edge strips, 7px off screen and above the page, the `html` and `body` backgrounds and one `theme-color` tag from the active theme's tokens, so mobile Safari's status bar and toolbar continue the studio. It adds `viewport-fit=cover` to the page's viewport tag and restores every change on dispose. It also writes `--dsh-viewport-height`, which the shell sizes itself to: the layout viewport, so the studio's surface reaches the physical top and bottom edges, except while the on-screen keyboard shortens the visual viewport, when it takes that instead so the composer stays above the keyboard. A pinned PWA on iOS reports a visual viewport that stops at the status bar and the home indicator, so the shell cannot follow it there; `edges.css` publishes the insets as `--delorun-safe-top` and `--delorun-safe-bottom`, and the surfaces pad their content by them.
