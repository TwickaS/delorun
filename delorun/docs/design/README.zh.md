# 设计

[English](README.md) | 中文

## 摘要

设计页面陈述 Delorun 为尚未构建或只构建了一部分的功能所采纳的规则：它做什么、拒绝什么、不防护什么，以及证明这一切的拒绝测试。[约定页面](../contracts/README.zh.md)只描述已构建的内容。设计页面让贡献者可以阅读一个未构建功能所采纳的规则，而不必让某份约定声称代码并不具备的行为。

每个设计页面都有相同的部分：摘要；今天已有的内容（对照代码核实）；规则；该设计不防护什么；它已有的拒绝测试；以及实现状态。“今天已有的内容”和“实现状态”下的陈述针对的是本仓库中的代码。规则下的陈述是设计，在有更改把它构建出来之前，其中没有任何一条成立。

## 设计如何变成约定

构建某个设计的更改，会把它的规则连同拒绝测试一起移入拥有这些规则的约定页面或一个新的约定页面，并在同一个 pull request 中把设计页面缩短为指向该约定的指针。只构建了一部分的设计，保留尚未构建的规则，并在“实现状态”下指出已构建的内容。陈述某项[安全基本原则](../security/fundamentals.zh.md)的设计，会在同一次更改中把该基本原则的行从 `designed` 移到 `enforced`，并附上证明它的代码和测试。

设计像其他任何文档一样通过 pull request 更改。削弱某项安全基本原则的设计更改，需要[基本原则页面](../security/fundamentals.zh.md#changing-a-fundamental)所描述的决定。

## 各项设计

- [更新与回退](update-and-rollback.zh.md)：更新报告的数据项、默认进行的 chat 数据副本、唯一的回退表、为什么回退不删除任何东西、对更低版本的拒绝，以及桌面应用的已验证更新。
- [更新通知](update-notice.zh.md)：不发送任何关于使用者的信息的、对更新发布版本的已验证检查，终端中的一行文字和侧边栏通知，关闭它的开关，补丁规则，以及插件如何以 Delorun 的版本为目标。
- [在你自己的 tailnet 上远程访问](reach.zh.md)：从你自己的设备打开 studio，只在 home 所在的电脑上批准设备，远程会话可以做和不可以做什么，以及回环凭据的记录与限制。
- [首次运行](first-run.zh.md)：从安装到第一次 chat 只需一条命令，启动器的进度，按使用场景进行的 setup，后台启动，以及 studio 中的新手引导。
- [对你的 harness 的更改](changes.zh.md)：你的 harness 是已签名的发布版本加上你所做的更改，每一项都有记录；审阅、应用和撤销更改，开发会话，保护设置以及保护关闭时什么会不经审阅就加载，以及更改造成问题时的恢复。
- [安全扩展点](security-extension-points.zh.md)：插件如何添加检查、警告、确认或拒绝，以及为什么它永远不能移除或覆盖内置检查。
- [可写工作区内的仓库设置](workspace-git-state.zh.md)：一个尚未决定的选项，即让受限命令对 `.git/config`、hooks 和 `.git/info` 只读，及其对模型自己的 `git config` 和 `git remote` 造成的代价。
- [必需的防护措施](required-guards.zh.md)：Delorun 组合出来之后又丢失的防护措施，会拒绝它的动作而不是让它在无防护的情况下运行，并且 headless 运行会挂载需要询问人的防护措施，使每一个在那里都拒绝。
- [旅程检查](journey-check.zh.md)：在干净容器中进行的一次端到端检查，从安装经由更新到回退，以及它不能证明什么。
- [在每条命令和每个平台上的原生约束](native-confinement.zh.md)：Delorun 在每条启动 Host 的命令下的保护，报告每条约束规则的检查，完全访问提示，Docker Desktop 的控制套接字，Windows，以及针对命令所做写入的指令同意。
- [导入的 chat 与定制](imported-chats.zh.md)：在使用者信任之前把导入的 chat 作为不受信任的来打开，在查看差异之后应用归档的定制，以及导入 stock DeepSeek Harness 的 home。
- [启动检查与身份记录](start-check.zh.md)：启动时比较每个运行时文件所记录的身份而不是对全部内容做哈希，完整哈希何时仍会运行，以及这种更便宜的检查能检测和不能检测什么。
- [后置启动检查之前的 studio](studio-before-check.zh.md)：只有当 Host 通过它的后置启动检查之后才提供 studio 链接，在此之前没有 studio 会话或模型请求。
- [Host 停止失败的退出码](host-stop-exit-code.zh.md)：Host 拆除失败或超时的停止，以失败码和一行日志结束。
- [发布工作流](release-workflow.zh.md)：发布已签名并已记录日志的发布版本的 CI 工作流，时间戳重新签名，无需令牌的 npm 发布，二选 N 的重新构建，Authenticode 和安装脚本。
- [模板](templates.zh.md)：已保存的、按内容寻址的、记录某人如何使用 harness 的记录；其中一个在 profile 中处于活动状态并保存此人自己的编辑，保存、切换、导入、导出、备份和恢复各自作为一次带重启的事务运行；以及当前工作为使模板保持可能而遵循的约束。
