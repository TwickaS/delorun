# 旅程检查

[English](journey-check.md) | 中文

> 英文页面是当前版本；本页可能落后于它。

## 摘要

旅程检查在干净的容器中运行一个人使用 Delorun 的整条路径：它安装发布版本、对其进行 setup、定制 profile、更新、在 chat 数据完好的情况下回退，并拒绝被篡改的发布版本。每一步都断言一个人会看到什么，并且每一步的构造都使有缺陷的产品会让它失败。它使用为本次运行生成的密钥和检查内部的服务器，绝不使用真实的发布密钥或线上服务。

## 今天已有的内容

目前不存在旅程检查。发布、安装和启动器各个包有它们自己的规格，它们针对本地替身运行各自的部分，而没有任何检查从干净的机器上把它们一起运行。

<a id="the-rules"></a>

## 规则

### 它在哪里运行

1. 该检查是[检查运行器](../../apps/tools/README.zh.md)合并层级中的 `journey`，带有声明的输入，所以没有改动其中任何一项的树会重用它已记录的通过结果。它是一个规格，由现有的 Docker 配置运行，独占机器。
2. 容器是一个干净的镜像，带有仓库所固定的主版本的 Node，不含仓库的任何东西，并且只能访问检查自己的服务器。

### 它的各个部分

| 部分 | 它是什么 |
| --- | --- |
| 密钥 | 为本次运行生成并随后丢弃的发布根、签名密钥和日志密钥；绝不使用真实的发布密钥 |
| 启动器 | 为本次运行构建，把本次运行的根以及本次运行的渠道和日志地址作为构建常量，如 [home 布局约定](../contracts/c01-home-layout.zh.md)所要求；没有任何设置可以移动它们 |
| 发布版本 1 | 由该树的 commit 构建 |
| 发布版本 2 | 同一个 commit，使用更高的版本，并带有一个其版本要求排除它的 fixture 插件，使更新报告中有一个条目 |
| 发布版本 2b | 带有永远不会就绪的 Host 的发布版本 2，所以健康检查必须失败 |
| 发布版本 3 | 由一个临时 commit 构建，该 commit 应用一个 fixture 补丁，在上游的源代码中提高某个存储单元的版本并附带其迁移，使持久化 schema 和真实存储的数据都发生变化；不再能应用的补丁会让检查带着该消息失败 |
| 渠道与日志 | 规格中的两个服务器：发布版本，以及一个可以一致、矛盾或保持沉默的日志替身 |
| 模型 | 上游的 mock 模型服务器，带有脚本化的序列 |

### 各步骤及每一步断言什么

1. 启动器包的 `npx` 在日志一致的情况下安装发布版本 1，并且 home 记录日志检查已运行并通过。`delorun setup` 带着脚本化的答案运行，而不是带着跳过它的变量运行。studio 的页面能够应答，默认 profile 挂载 fork 所列出的每一行，并且脚本化的 chat 能够完成。
2. 日志保持沉默时，全新安装会发出警告、继续，并记录检查没有运行。日志与发布版本相矛盾时，它会拒绝。
3. 定制 profile：移除一个 bundle、关闭一行、把一个插件从它的 bundle 中取出、一个 profile 补丁、一个预设、一个 skill 和一个主题。
4. `delorun update` 到发布版本 2，会在任何东西改变之前打印指出 fixture 插件的报告。人确认之后，健康检查通过，并且每一项定制都仍然存在。
5. `delorun recover rollback` 回到发布版本 1，定制和 chat 完好无损，并且发布版本 1 能读取发布版本 2 写下的每一条 Delorun 记录。
6. 更新到发布版本 2b 会自行回退，并指出失败的判据。
7. 更新到发布版本 3 会指出数据更改并制作副本，并写入第二个 chat。回退会恢复第一个 chat（在发布版本 1 下可读），把第二个搁置一旁并说明这一点。没有这次恢复，发布版本 1 会拒绝已迁移的存储单元，所以什么都不做的恢复会让这一步失败。
8. 同样的更新但带 `--no-data-copy`：回退以 `ROLLBACK_NEEDS_DATA_COPY` 拒绝，而 `--profile-only` 成功。
9. 某个制品中改变了一个字节的发布版本，会在安装之前被拒绝。

<a id="what-this-does-not-protect-against"></a>

## 本设计不防护什么

旅程检查不涵盖 npm 注册表及其证明、安装脚本、真实发布版本中附带的根、真实的公开发布日志、tailnet 路径、桌面应用、其他 Node 主版本、Windows 或 macOS。这些保留它们自己的检查，或在发布时手工检查。

<a id="denial-tests"></a>

## 拒绝测试

该检查本身就是第 2、7、8 和 9 步的拒绝测试：安装了日志矛盾的发布版本、不进行恢复的回退、没有副本却不拒绝的回退，以及安装了被篡改的发布版本，每一种都会让它失败。

## 实现状态
