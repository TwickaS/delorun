# Parity checklist

English | [中文](parity.zh.md)

The parity checklist records, for each stock DeepSeek Harness (DSH) area that Delorun is compared against and for each deliberate difference, the status of that area in this tree and one piece of evidence. Every row names its baseline, the recorded upstream tag `dsh-v0.2.2-rc.3`, which the [parity composition](../../contracts/c16-parity-composition.md) replays. The page covers the areas below, the switches and changed defaults that the parity composition contract lists, and the differences that the [switching page](../../guide/get-started/switching.md) names. It does not inventory every stock feature.

## How rows are judged

The status column states what this tree does. `built` means the change is in the tree: the row names its switch ID, or, for a Delorun change that has no switch, says `no switch` and names its ledger entry. `planned` means the change is not in the tree: the row names the switch ID and work package from the registry or, where the registry has no entry, the C16 changed default or the contract that defines it. `stock` means upstream's behaviour at the baseline is unchanged in the area.

Each row gives one evidence. A check name, such as `parity-switches`, runs `node_modules/.bin/tsx delorun/apps/tools/src/parity/composition/check-parity-switches.ts`, which reads the switch registry, the switch fields and the parity overlay. A spec path names a test file that asserts the row. An entry that begins with Manual check: names the source lines that a reviewer reads to confirm the row.

Twelve built switches have a switch-on scenario that is pending recording: `browser_additions`, `main_chat`, `rename_workspace_tool`, `permission_defaults`, `fetch_guard`, `scheduled_task_consent`, `instruction_layer_consent`, `mcp_add_consent`, `external_agent_consent`, `sandbox_protected_reads`, `update_turn_refusal` and `default_workspace_directory`. `parity-switches` reports each one as pending, not as passing, so this page claims no replay result for them. The model-visible switches `preset_inspect`, `plugin_manager_read_exemption`, `profile_history`, `container_denial_marker`, `tool_failure_guard` and `use_my_browser` have a recorded scenario under `snapshots/`, which the parity replay runs under the overlay.

## Deliberate differences

Each difference below is one that Delorun's documents name or that C16 lists. The rows are grouped by topic.

Setup's prompts answer sets four of the switches below: `permission_defaults`, `instruction_layer_consent`, `mcp_add_consent` and `scheduled_task_consent`. "Ask me first", the default, turns them on in the profile, and "Ask less (like DeepSeek Harness)" turns them off there, which is each one's parity value. `fetch_guard` and `external_agent_consent` stay on whichever answer is given (`apps/cli/src/setup/prompt-switches.ts`).
