# Security fundamentals

English | [中文](fundamentals.zh.md)

## Summary

A security fundamental is a rule about what Delorun does or refuses that a person can rely on in every release. Each one is stated in one sentence, with the code that enforces it and the test that fails when that code stops enforcing it. An `enforced` fundamental holds on the code in this repository today. A `designed` fundamental is a rule Delorun has adopted whose code is not built yet; its [design page](../design/README.md) states how it will hold, and the change that builds it moves the row to `enforced`.

A protection can make a fundamental stricter, and nothing weakens or removes one without the decision described in [Changing a fundamental](#changing-a-fundamental). The [security extension points design](../design/security-extension-points.md), which is not built, lets a plugin make Delorun stricter and never weaker.

## How the list is checked

The `gates:fundamentals` gate of [the check runner](../../apps/tools/README.md) reads the table above. It fails when a column is missing, an id repeats or is not `F` and a number, or a status is neither `enforced` nor `designed`. For an `enforced` row it fails when a named file does not exist, or when the spec file holds no `it` or `test` whose title, or `.each` template, equals the quoted title; a skipped test does not count. It prints the number of fundamentals in each status.

The gate checks that the named test exists, not that it fails when the check is removed. Review checks that, as it checks every denial test.

## Changing a fundamental

Changing the list, by adding a fundamental, changing what one states or removing one, needs a maintainer decision recorded as an [Agent Note](../../../.agents/notes/README.md) and a changelog fragment in the Security section ([changelog](../../changelog/README.md)), both in the same pull request as the change to this page ([governance](../../../GOVERNANCE.md#decisions)). Moving a row from `enforced` back to `designed` weakens it and needs the same decision. Two edits change no fundamental and need neither: moving a row from `designed` to `enforced` in the change that builds its code and tests, and updating the paths and titles when a change moves the code or renames the test.
