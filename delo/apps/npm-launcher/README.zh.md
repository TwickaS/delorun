# @delo/npm-launcher

[English](README.md) | 中文

## 摘要

此应用即 `npx delorun` 运行的内容。它启动本机已安装的运行时，若没有可启动的运行时，则先安装频道指定的发布。启动不需要网络：约定 C2 的启动检查在运行时存储内部运行，因此与签名文件清单不再相符的运行时不会启动。安装经由 [`@delo/install`](../install/README.zh.md) 完成，它会依据签名清单与发布日志校验该发布；任一检查拒绝时，`~/.delo/runtimes/` 下不会留下任何内容。启动器从不切换 `current`：切换由存储的安装完成，且只在存储完全没有运行时的情况下发生。

<a id="commands"></a>

## 命令

| 命令行 | 作用 |
| --- | --- |
| `delorun [--profile <name>]` | 以给定的参数启动已安装的运行时；存储中没有运行时时先安装频道指定的发布 |
| `--profile <name>` | CLI profile，同时传给运行时；默认为 `default`，未提供该标志时由 `DELO_PROFILE` 提供 |
| `--release <version>` | 安装此发布而非频道的当前发布；新时间戳未指定的发布会被拒绝 |
| `--help`、`-h` | 打印用法说明 |
| 其他任何参数 | 原样传给运行时，因为 `delorun` 的命令由运行时拥有 |

<a id="the-launch-flow"></a>

## 启动流程

`runLauncher` 先尝试启动，仅在存储回答 `NO_ACTIVE_RUNTIME` 时才安装。启动会读取 `trust/root.json`（本 home 最近校验通过的根）并交给存储，由存储对 `current` 运行约定 C2 的启动检查，并构建约定 C1 的启动协议 1 命令。没有已存储的根时按没有运行时的存储处理，因为本 home 还没有校验过任何内容。

安装会解析发布，请存储以频道的 `fill` 作为下载步骤来安装它，然后保留指针所指的两个版本并移除其余版本。存储无法完成的清理会作为警告报告，并在下次运行时重试；它从不会让启动失败。

运行时取代本进程运行：启动器用存储构建的环境启动它，与其共享标准输入输出，并以运行时自身的状态退出。

<a id="the-roots-it-ships"></a>

## 它随包携带的根

启动器只通过自己包内 `roots/` 目录中的根文件（`1.root.json`、`2.root.json` 及以后）信任一个发布。更新的根只能从本包携带的最新根逐级走到，因此根版本出现缺号的包会拒绝任何安装，而不会信任网络提供的内容。完全没有根的包会以 `NO_TRUSTED_ROOT` 拒绝任何安装，并提示对方改用发布页面上的安装脚本。

<a id="refusals"></a>

## 拒绝

`refusalFor` 把任何失败变成标准错误上的一句话：Delo 做了什么、为什么，以及对方可以怎么做。安装类拒绝会指明相关的发布、主机或文件，并给出该代码所带的可行动项：

- 主机不可达或日志无法检查时，提示对方检查连接并再次运行同一命令。
- 没有可信根的启动器会指向发布页面上的安装脚本。
- 无法读取的信任文件提示对方把它移开；启动器会在校验通过后重新存储它。
- 被拒绝或无法校验的发布，提示对方在发布页面列出更新发布时再次运行同一命令，并在重复出现时报告。

存储类拒绝会把存储自身的可行动项作为对方可以运行的命令提供，例如重新安装该发布，或切回为回滚保留的版本。

<a id="exit-codes"></a>

## 退出码

| 代码 | 何时 |
| --- | --- |
| 0 | 运行时运行并以状态 0 结束，或已打印用法说明 |
| 1 | Delo 拒绝或失败且没有运行任何内容，或运行时以自身的非零状态结束 |
| 2 | 命令行有误 |

<a id="development"></a>

## 开发

`tests/` 中的测试用替身存储、频道与启动过程驱动 `runLauncher`，因此不访问网络，也不会在运行测试的机器上安装任何内容。用仓库的 Vitest 配置运行：`node_modules/.bin/vitest run --config delo/vitest.config.ts delo/apps/npm-launcher`。
