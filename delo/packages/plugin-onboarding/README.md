# @delo/plugin-onboarding

## Summary

The studio's first minute is one dialog that ends in a chat. It opens on the preview notice, then asks for the language and look, offers the Claude Code and Codex delegation bundles, offers the recommended plugins, explains reach where reach is available, and finishes by opening a new chat in the default workspace, or in a folder the person chooses where there is no default workspace; a folder Delo never adds as a workspace, such as the home folder itself, is refused with the reason and what to do instead. That chat's empty state offers three starting prompts that write into the message box and send nothing. Onboarding leaves out what the terminal setup already covered, shows again from Settings → About, and loads only while the Delo look is on: with the stock look, the preview notice keeps its own step.

## The steps

| Step | Shown | What it does |
| --- | --- | --- |
| Preview notice | On the first run, while this browser has not acknowledged the notice | Shows the notice's title and paragraphs from `@delo/bundle-local`'s dictionary. Continue records the acknowledgement through `ctx.deloNotice`, so the notice's own step then completes without a second dialog. Without `ctx.deloNotice` the screen is left out. |
| Language and look | Always | Chips for the language (upstream's locale service), the colour scheme, the palette with a light and dark preview, and the accent presets while the Soft palette is chosen. A last choice, Delo or Stock, says before it is made that the stock look turns Delo's studio additions and this guide off, that Settings → Appearance switches between the two, and that with the stock look on the Delo look row in Settings → General turns them back on. Each set of chips is one labelled radio group with one tab stop, on the chosen chip; the arrow keys move to the next or previous chip and choose it, wrapping, and Home and End move to the first and last. In the Delo or Stock set the keys only move focus and Space or Enter chooses, so an arrow key never turns Delo's look off. |
| Agents | Always | Cards for `@deepseek-ai/dsh-subagent-claude-code` and `@deepseek-ai/dsh-subagent-codex` with their state from the plugin manager. The copy says that Claude Code and Codex run as their own programs, with their own permissions, outside Delo's permission prompts. A card adds its bundle only when the person presses Add, whose accessible name says what it adds, such as Add Claude Code. A bundle this installation cannot install shows Not included in this installation with an Open Plugins button, which is a normal state and not an error. |
| Recommended plugins | When the row's `plugins` list is not empty | A card per configured package, with the title and description the plugin manager lists for it, and the same Add button, named after the card's title. |
| Reach | Only while `ctx.deloReach` exists and says reach is not set up, and the terminal setup record does not say it is, including after a skip | Says that reach opens this studio from a phone, that it is turned on at the computer that runs Delo with `delorun reach on tailscale`, and that a phone session cannot grant full access or approve devices, which the [reach design](../../docs/design/reach.md) states and no built code enforces. Without `ctx.deloReach` the step is left out, and no plugin provides it. |
| Start | Always, last | Says where the chat opens. It records that onboarding is done and opens a new chat in the default workspace. Where no default workspace resolves it says so and its button is Choose a folder, which opens the host's native chooser or, where the host has none, the step's own chooser. A folder Delo refuses keeps the dialog open with the reason. |

Steps other plugins add through `ctx.deloOnboarding` sit between Reach and Start. Skip for now, on every screen but the notice, records that onboarding is done and opens no chat, and focus moves to the page's message box. Settings → About has a row, `delo-onboarding`, whose Show again button reopens the flow from Language and look and keeps every other setting; the reopened flow counts as unfinished, so a reload shows it again until it is finished or skipped.

The step's own chooser lists the folders of one folder at a time in a labelled list, starting at the home directory, with hidden folders left out. Nothing is selected when it opens or after a move, so Add this folder waits until the person selects a folder or creates one, and the folder the chooser opened in is never added by default. A click or the arrow keys select a folder; a double click, Enter, the right arrow or Open folder enters it; Up one folder and the left arrow go up; New folder creates a folder in the shown folder and selects it. A refused folder shows its reason in place, and a folder that cannot be listed or created says so with a way on.

The starting prompts show above the message box of the chat the last button opened, until that chat has a message, the person types something of their own, or the person hides them. Their text is in the dictionary, so each language has its own.

## Contract

- **Stock look.** The studio half injects `deloStudio` inside `apply` (`ctx.inject(['deloStudio'], applyStudio)`), so its entry stays active under the stock look, which upstream's web boot requires of every entry. `@delo/plugin-theme` provides that service only while the Delo look is on, so without it the plugin registers nothing and provides no service. `settingsShell`, which the Settings shell provides under every look, is in the top-level `inject`: Show again calls `ctx.settingsShell.openOnboarding`, which cordis refuses on a service the plugin did not inject.
- **The onboarding step** is a `settings.onboarding` entry with the id `delo-onboarding` at order -200, before `delo-notice` (-100) from `@delo/bundle-local` and the model step of upstream. It registers only while the host serves the row `delo-onboarding`. With `done` set and no `explicit` flag it calls `complete()` at once, and so does a row that cannot be read. The dialog owns the page's inert root while it shows, takes focus to the step's heading at each step and is closed only by its buttons. When it closes, the root stops being inert before upstream's modal layer puts focus back; if focus is then on the document body, it moves to the message box (on a phone or tablet, to the message box's card, so the keyboard stays down), or else to the page's first control. Only the step's own chooser has a text field, the new folder's name, which shows when the person asks for it.
- **Progress** is the row's volatile configuration: `done`, `step` (the id of the step reached, which resumes the flow) and `starterSession`. Show again writes `done: false` and an empty `step` before it asks the Settings shell to open the step. A write that fails is logged and the flow goes on. The notice screen is shown from the start while it is owed, whatever step was saved.
- **Language and look** write only the theme row's `palette` and `accent` through `ctx.configForms`, and the colour scheme through upstream's theme service. Choosing Stock calls `ctx.deloStudio.useStockLook()`, which unloads this plugin. Palette and accent labels come from `@delo/plugin-theme`'s dictionary `settings.deloAppearance`, and the preview colours in [`src/client/previews.ts`](src/client/previews.ts) are copies that a test compares with the theme's own.
- **Agents and plugins** use the plugin manager's remote namespace, read from the store as the `remote.pluginManager` service (a property access on `remote` reaches a namespace only for a plugin that injects it, and injecting it would hold the guide until a plugin manager mounts). `listBundles` only reads. A bundle the installation ships is switched on with `setBundleEnabled`; a catalog entry is installed from its `installTarget` with `installBundle` and then enabled. A result of `applied` shows Added, `restart-required` shows that Delo needs a restart, and anything else, or a plugin manager that cannot be asked, shows a failure with a button that opens Plugins. A catalog entry with no install target, or with an error beside its target (such as a source checkout whose built runtime is missing, or an unsupported platform), is not installable here: it shows Not included in this installation with the same button. Nothing installs without a press.
- **The setup record.** The harness half requires `connection` and serves one exact route, `GET /api/deloOnboarding.setupRecord`, uncached ([`src/wire.ts`](src/wire.ts)). It answers `{ sections?, reachSetUp }` from `setup-answers.json` in the CLI profile's directory (`ctx.profileContext.dir`), which `delorun setup` writes and onboarding never writes. `reachSetUp` is true when `reach.option` is a non-empty string other than `none`; `sections` is the list of lower-case section names (at most 32, each up to 40 characters) when it validates. Only these two fields are read, other fields are tolerated and never served or logged, a file over 64 KiB or that is not a regular file is not read, and a missing, unreadable or invalid file answers `{ reachSetUp: false }` so every step shows. A reason is logged without quoting the file. The studio parses the answer strictly and treats any failure the same way.
- **Sections.** A section name equal to `look`, `agents` or `plugins` leaves that step out. The notice, Reach and Start are never left out by name; Reach follows `ctx.deloReach` and `reachSetUp`.
- **First chat.** When the dialog opens it calls `ctx.workspaces.initializeDefault()` once, which the host answers with the existing default workspace and creates one only while it holds no workspace and no chat, so the Start step knows what its button does. The last button calls `ctx.uiWorkspace.openWorkspace` and writes the opened chat's id to `starterSession` before the chat is shown. Where the lookup resolves nothing or fails and other workspaces exist, the workspace UI's own New Session applies and no prompts follow. Where it resolves nothing and no workspace exists, the Start step says so and its button is Choose a folder: it calls `ctx.uiWorkspace.pickDirectory()` and adds the folder through the add-workspace route, then opens a chat there with the prompts. A closed chooser keeps the dialog open. Where the host has no native chooser (`pickDirectory` fails, as on a host whose chooser is a page dialog), the Start step shows its own chooser over `ctx.uiWorkspace.listDirectory` and `createDirectory`, and the footer's button gives way to the chooser's Add this folder. A refusal or a failure to add keeps the dialog open with the reason. Without `ctx.uiWorkspace`, New Session applies and no prompts follow. The workspace UI's own startup lookup raises the notice `defaultWorkspaceFailed` when the default workspace cannot be created. While the dialog shows it holds that notice through `ctx.uiWorkspace.holdDefaultWorkspaceNotice()`; when the dialog closes the notice is dropped if the Start step said there is no default workspace, and shows otherwise, for example after Skip. The prompts are an entry in `conversation.input.dock` (id `delo-onboarding.starters`, order 10). A chip calls `setDraft` on that chat's input through `ctx.sessions` and `ctx.conversation`, and focuses the box only for a pointer that can hover, so a phone keeps its keyboard down. While `starterSession` is `pending`, the first empty chat whose input dock mounts takes the prompts (`starterSession` becomes its id); onboarding itself writes only a chat's id.
- **Adding a folder.** While upstream's workspace registry is present, the harness half serves one exact route, `POST /api/deloOnboarding.addWorkspace` ([`src/workspace-route.ts`](src/workspace-route.ts)). A `connection/request` listener refuses, before the body is read, any request that did not arrive on the loopback listener under a loopback `Host` (the arrival test of the device routes: the listener the mounted `homeAuth` service reports for the request, read when it arrives, and `@delo/home-auth`'s `isLoopbackHost`); with no `homeAuth` service mounted, or one that cannot place the request, it refuses too: 403 with `{ error: 'LOOPBACK_ONLY', message }`, because a workspace decides what the model may write and only the person at the computer chooses it. It takes `{ path }` (JSON, at most 4096 characters, a body of at most 24 640 bytes) and holds the path against `workspaceLocationProblem` from `@delo/home`, with the Delo home resolved from the environment as every Delo plugin resolves it (`delorun` gives the harness the same directory as `DSH_HOME` and `DELO_HOME`). The filesystem root, the home directory itself, the Delo home or a folder inside it, a folder that contains the Delo home, the stock home `~/.dsh` or a folder inside it, a folder that contains the stock home, and a relative path are refused with 422 `{ result: 'refused', problem }`, and nothing is registered. Any other folder is registered with `workspaceRegistry.create` and answered with 200 `{ result: 'added', workspaceId }`. A request it cannot read answers 400; a Delo home that cannot be resolved or a folder the registry refuses answers 500 `{ result: 'failed' }`, with the failure's code, never its path, in the log. Without the registry the route is absent and the studio reports a failure. The studio parses the answer strictly and shows each problem's reason and what to do instead in its own copy.
- **`ctx.deloReach`** is an optional service the reach plugin provides when reach can be turned on in this installation: `interface DeloReach { readonly available: true; setUp(): boolean }`, where `setUp()` says whether reach is already on at this computer. Onboarding reads it with `ctx.get('deloReach')`, follows it as it comes and goes, and shows the Reach step only while it exists and `setUp()` is false and the setup record does not say `reachSetUp`. No plugin provides it yet, so the step is hidden. The step's copy names that one command and no other way to reach.
- **`ctx.deloOnboarding.registerStep(step)`** adds an `OnboardingStep` (`id`, `order` 600 to 999, `title`, `component` taking `next`) and returns its disposer; a step with an earlier step's id replaces it.
- **Copy** is in English and Chinese ([`src/client/locales.ts`](src/client/locales.ts)) under the namespace `deloOnboarding`; the Plugins page names the plugin from [`locale/`](locale/en.json). CSS uses theme tokens only: `--delo-space-*` for spacing, upstream's font tokens for type, and no label weaker than the secondary label for any text. Below 768 px the dialog is the whole window, the list of steps becomes a count with a bar, and the footer stays at the bottom; the chooser's rows wrap long names and grow to 44 px for a coarse pointer.

## Configuration

The row `delo-onboarding` has four volatile fields ([`src/config.ts`](src/config.ts)), validated when the configuration loads and changeable while the studio runs.

| Field | Default | Meaning |
| --- | --- | --- |
| `done` | `false` | Whether the person finished or skipped onboarding. |
| `step` | empty | The id of the step reached. |
| `starterSession` | empty | The chat whose empty state offers the starting prompts. |
| `plugins` | empty | Up to eight npm package names the recommended-plugins step offers. With none, the step is left out. |

`plugins` is empty by default: no Delo plugin on this base is a recommendation, and an empty list leaves the step out instead of showing an empty screen. A deployment sets the list in `cordis.yml`.

## Limits

- **Delegation consent.** Adding Claude Code or Codex asks for nothing beyond the press of Add, and Delo asks nothing before a delegated agent acts. The per-workspace consent for a first delegation is not built on this base, and the Agents step does not say it exists.
- **Reach.** No plugin provides `ctx.deloReach` yet, so the Reach step never shows. The command it names, `delorun reach on tailscale`, belongs to the reach plugin.
- **Folder chooser.** Onboarding's refusals cover only the folders it adds. Upstream's own add-workspace flow and `workspace.create` register any existing directory, the home directory included; under Delo, where the sandbox protects the Delo home, every shell command that runs with write access in a workspace that is, lies inside or contains the Delo home then fails with `HOME_IN_WRITABLE_ROOT`. The step's chooser has no path field and no way to show hidden folders.
- **Section names.** The terminal setup writes a `sections` record (schema versions 2 and 3): one `{ id, status }` row per section it showed. The harness serves the ids whose status is `seen` or `answered`, and the flow leaves out a step whose id is among them; a `skipped` row covers nothing. Reach is decided by the reach answer and the `deloReach` service, not by this list.

## Tests

`node_modules/.bin/vitest run --config delo/vitest.config.ts --maxWorkers=2 packages/plugin-onboarding/` runs the specs; add `--coverage.enabled --coverage.provider=v8 --coverage.reporter=text --coverage.include='packages/plugin-onboarding/src/**'` for coverage, which is complete.

- [`tests/host.spec.ts`](tests/host.spec.ts) checks the configuration's validation, the record reader with a missing, malformed, oversized, directory-named and hostile file (no field outside the two used is served, and no log line quotes the file), and the route.
- [`tests/workspace-route.spec.ts`](tests/workspace-route.spec.ts) checks the add-workspace route: that it exists only with the registry, that a request a reach listener admitted, one under a non-loopback `Host`, one the service cannot place and any request while no `homeAuth` service is mounted are refused with 403 before the route and that the loopback listener and other paths pass, adds a folder inside the home directory, refuses each location Delo never adds (and a link to the home directory) without asking the registry, answers 400 to requests it cannot read, logs a registry failure by its code only, and names the same problem codes as `@delo/home`.
- [`tests/steps.client.spec.tsx`](tests/steps.client.spec.tsx), [`tests/bundles.client.spec.tsx`](tests/bundles.client.spec.tsx) and [`tests/dialog.client.spec.tsx`](tests/dialog.client.spec.tsx) check each step, the radio groups' tab stop and keys, the named Add buttons, that bundles install only on a press, the notice acknowledgement and its absence, finished progress, a reopened flow, resume, skipping, the steps left out, the folder choice with its refusals and the step's own chooser, and where focus lands when the dialog closes.
- [`tests/chooser.client.spec.tsx`](tests/chooser.client.spec.tsx) checks the step's own chooser: nothing selected when it opens, so its button is disabled; adding the selected folder; each refusal's reason; entering a folder, going up, keys, creating a folder; listing failures; and that only the newest listing shows. [`tests/focus.client.spec.tsx`](tests/focus.client.spec.tsx) checks where focus lands.
- [`tests/plugin.client.spec.tsx`](tests/plugin.client.spec.tsx) checks that nothing registers without `deloStudio`, the registrations and their disposal, that Show again opens the dialog through a Settings shell that loads after the plugin and keeps it unfinished across a reload, the reach service following `ctx.deloReach`, the record loader, the default workspace lookup, choosing and adding a folder through the route, opening the first chat and its fallbacks, and the starting prompts' services.
- [`tests/starters.client.spec.tsx`](tests/starters.client.spec.tsx) checks that a chip writes the draft and sends nothing, when the prompts show, and which chat takes them while they are pending.
- [`tests/previews.spec.ts`](tests/previews.spec.ts) compares the preview colours with the theme's, and [`tests/locales.spec.ts`](tests/locales.spec.ts) the English and Chinese copy.
