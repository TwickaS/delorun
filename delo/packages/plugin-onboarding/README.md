# @delo/plugin-onboarding

## Summary

The studio's first minute is one dialog that ends in a chat. Welcome sets the language, shows the preview notice and tests each model provider's key with the provider's free model listing, with Settings → Models drawn inside the step to add or change a provider. Look sets the colour scheme, theme and accent beside a small chat in that look. Agents offers Claude Code and Codex with their sign-in on this computer and asks the person to confirm what adding one means. Recommended plugins offers the configured plugins, those that fit the person's connections first. Phone access shows how far Tailscale is from serving the studio, while reach is off. Workspace chooses the default workspace, a folder on this computer or a repository cloned from Git. Ready lists what the guide set and opens the first chat, whose empty state offers three starting prompts for what the folder holds; a prompt writes into the message box and sends nothing. Onboarding leaves out what the terminal setup already covered, shows again from Settings → About, and loads only while the Delo look is on.

## The steps

| Step | Shown | What it does |
| --- | --- | --- |
| Welcome | Always, first | Language chips (upstream's locale service). While the preview notice is owed (it exists, this browser has not acknowledged it and onboarding was not reopened), its title and paragraphs from `@delo/bundle-local`'s dictionary, and Continue records the acknowledgement through `ctx.deloNotice`, so the notice's own step completes without a second dialog; Skip is hidden until then. One row per model provider route with its key test: Key works, The provider rejected this key, Could not reach the provider, No key saved, No free test for this provider, or Could not test this key. Add or change providers draws upstream's Models section in the step; closing it tests the keys again, and so does Test again. |
| Look | Unless the setup record covers `look` | Chips for the colour scheme (upstream's theme service), the palette with a light and dark swatch, and the accent presets while the Soft palette is chosen, beside a chat drawn in the chosen look. A last choice, Delo or Stock, says before it is made that the stock look turns Delo's studio additions and this guide off and that Settings → Appearance switches back. Each set of chips is one labelled radio group with one tab stop, on the chosen chip; the arrow keys move and choose, wrapping, and Home and End move to the ends. In the Delo or Stock set the keys only move focus and Space or Enter chooses, so an arrow key never turns Delo's look off. |
| Agents | Unless the setup record covers `agents` | Cards for `@deepseek-ai/dsh-subagent-claude-code` and `@deepseek-ai/dsh-subagent-codex` with their state from the plugin manager and their sign-in on this computer: signed in, not signed in with the command that signs in, or that Delo cannot tell. Add opens a group that says what adding the agent means: when an agent starts from a chat, Delo asks on this computer first unless the person allowed it for that workspace, and a phone cannot answer; read-only chats never start one, runs stay in the chat's workspace and stop after 30 minutes, and Settings → Permissions revokes it; it runs outside Delo's sandbox and permission prompts; it can read and change any file its own settings allow, Delo's files included; and its use is billed to its own sign-in. A second button adds the bundle. A bundle this installation cannot install shows Not included in this installation with an Open Plugins button. |
| Recommended plugins | When the row's `plugins` list is not empty and the setup record does not cover `plugins` | A card per configured package with the title and description the plugin manager lists. A package that declares [connections](#connections) the person has comes first with Fits and their names; one that declares none follows them without a note; one that declares only connections the person lacks is left out, and when every package is left out the step says so. Packages that are not installed are read from the npm registry only after the person presses Check plugins that are not installed online. |
| Phone access | While the reach status route answers that no reach option is ready and the setup record does not say reach is set up | Four checks in the order a person fixes them: Tailscale installed, this computer signed in, HTTPS certificates on for the tailnet, and the person's user allowed to configure `tailscale serve`. Each shows done, the first one missing shows its fix (a link, a command with a copy button, or the admin console setting), and the rest wait. Then `delorun reach on tailscale` and `delorun devices approve`, each with a copy button, and the address the phone opens once Tailscale names this computer. It says that a phone session cannot grant full access or approve devices, and that Delo works on this computer without reach. |
| Workspace | Always | Default workspace (when one resolves), A folder on this computer, or Clone from Git. A folder comes from the host's native chooser or, where the host has none, the step's own chooser. A clone takes an address, the folder to clone into (picked with the step's chooser) and the new folder's name, which follows the address until the person types one; it shows Git's percent while it runs and, when it fails, why. The chosen folder shows with what it holds: a code project, a folder of files, or an empty folder. |
| Ready | Always, last | A line each for the model (the providers whose key works, or that none does), the look, the agents and plugins added, phone access where the home has reach, and the workspace, with the starting prompts the first chat will offer. Start a chat records that onboarding is done and opens a new chat in the chosen workspace. When no workspace is chosen and none resolves, Start a chat goes back to Workspace. |

Steps other plugins add through `ctx.deloOnboarding` sit between Phone access and Workspace. Back, Continue and Skip for now sit under every step; Skip records that onboarding is done, opens no chat, and moves focus to the page's message box. Settings → About has a row, `delo-onboarding`, whose Show again button reopens the flow from Welcome and keeps every other setting; the reopened flow counts as unfinished, so a reload shows it again until it is finished or skipped.

The step's own chooser lists the folders of one folder at a time in a labelled list, starting at the home directory, with hidden folders left out. Nothing is selected when it opens or after a move, so its button waits until the person selects a folder or creates one. A click or the arrow keys select a folder; a double click, Enter, the right arrow or Open folder enters it; Up one folder and the left arrow go up; New folder creates a folder in the shown folder and selects it. A refused folder shows its reason in place, and a folder that cannot be listed or created says so with a way on.

The starting prompts show above the message box of the chat Ready opened, until that chat has a message, the person types something of their own, or the person hides them. They follow what the folder holds (general, empty, code or files), and their text is in the dictionary, so each language has its own.

## Contract

- **Stock look.** The studio half injects `deloStudio` inside `apply` (`ctx.inject(['deloStudio'], applyStudio)`), so its entry stays active under the stock look, which upstream's web boot requires of every entry. `@delo/plugin-theme` provides that service only while the Delo look is on, so without it the plugin registers nothing and provides no service. `settingsShell`, which the Settings shell provides under every look, is in the top-level `inject`: Show again calls `ctx.settingsShell.openOnboarding`.
- **The onboarding step** is a `settings.onboarding` entry with the id `delo-onboarding` at order -200, before `delo-notice` (-100) from `@delo/bundle-local` and upstream's DeepSeek key step `deepseek-official`. It registers only while the host serves the row `delo-onboarding`. With `done` set and no `explicit` flag it calls `complete()` at once, and so does a row that cannot be read. Welcome draws the Models section through the seat's `renderSection('models')`. Start a chat also calls `completeStep('deepseek-official')`, because Welcome offered the same providers. `@delo/bundle-studio` sets `credentialOnboarding: false` on `ui-settings-models`, so upstream's key step never opens, also after Skip or a reload. The dialog owns the page's inert root while it shows, takes focus to the step's heading at each step and is closed only by its buttons. When it closes, focus moves to the message box (on a phone or tablet, to the message box's card, so the keyboard stays down), or else to the page's first control.
- **Progress** is the row's volatile configuration: `done`, `step` (the id of the step reached, which resumes the flow), `starterSession` and `starterKind`. Show again writes `done: false` and an empty `step` before it asks the Settings shell to open the step. A write that fails is logged and the flow goes on.
- **Look** writes only the theme row's `palette` and `accent` through `ctx.configForms`, and the colour scheme through upstream's theme service. Choosing Stock calls `ctx.deloStudio.useStockLook()`, which unloads this plugin. Palette and accent labels come from `@delo/plugin-theme`'s dictionary `settings.deloAppearance`, and the preview colours in [`src/client/previews.ts`](src/client/previews.ts) are copies that a test compares with the theme's own.
- **Agents and plugins** use the plugin manager's remote namespace, read from the store as the `remote.pluginManager` service. `listBundles` only reads. A bundle the installation ships is switched on with `setBundleEnabled`; a catalog entry is installed from its `installTarget` with `installBundle` and then enabled. `applied` shows Added, `restart-required` shows that Delo needs a restart, and anything else, or a plugin manager that cannot be asked, shows a failure with a button that opens Plugins. A catalog entry with no install target, or with an error beside its target, shows Not included in this installation. Nothing installs without a press.
- **Routes.** The harness half requires `connection` and serves these exact routes ([`src/wire.ts`](src/wire.ts)), each answering JSON uncached. The studio parses every answer strictly and shows an honest state for a route it cannot read. None is on `@delo/home-auth`'s device paths, so the authenticator refuses a signed-in phone every route; the three loopback-only routes also refuse it themselves.

  | Route | Answers |
  | --- | --- |
  | `GET /api/deloOnboarding.setupRecord` | `{ sections?, reachSetUp }` from the terminal setup record. |
  | `GET /api/deloOnboarding.readiness` | Claude Code's and Codex's sign-in (`found`, `missing` or `unknown`) and Tailscale's state with this computer's DNS name. |
  | `POST /api/deloOnboarding.keyTest` | Each model provider route's name and result: `works`, `rejected`, `unreachable`, `no-key`, `untested` or `failed`. |
  | `POST /api/deloOnboarding.recommend` | Each configured plugin's declared connections, where they were read, and whether the registry was reached. |
  | `POST /api/deloOnboarding.addWorkspace` | Loopback only. `added` with the workspace id and folder kind, or `refused` with the problem. |
  | `POST /api/deloOnboarding.clone` | Loopback only. `started` with a job id, or `refused` with the problem. |
  | `POST /api/deloOnboarding.cloneStatus` | Loopback only. `running` with a percent, `done` with the workspace and folder, `failed` with the reason, or `unknown`. |

- **The setup record** is read from `setup-answers.json` in the CLI profile's directory (`ctx.profileContext.dir`), which `delorun setup` writes and onboarding never writes. `reachSetUp` is true when `reach.option` is a non-empty string other than `none`; `sections` lists the section ids whose status is `seen` or `answered` (at most 32, each up to 40 characters). Only these fields are read; a file over 64 KiB, one that is not a regular file, or one that is missing, unreadable or invalid answers `{ reachSetUp: false }`, so every step shows. A reason is logged without quoting the file. A section named `look`, `agents` or `plugins` leaves that step out; Welcome, Workspace and Ready are never left out.
- **Readiness** only reads. The sign-in check tests whether `~/.claude/.credentials.json` or Codex's `auth.json` (in `CODEX_HOME`, else `~/.codex`) exists and never opens it (Claude Code's file is in `CLAUDE_CONFIG_DIR` when that is set); on macOS, where Claude Code keeps its sign-in in the keychain, a found `~/.claude.json` answers `unknown`. The Tailscale check runs `tailscale version`, `tailscale status --json` and `tailscale serve status --json` through `@delo/reach`'s runner, and no command that changes anything.
- **The key test** asks each provider route for its model listing, never a completion, so it spends no tokens. A route whose adapter registered a model discovery is asked through upstream's `llm.discoverModels`, which uses the stored key inside the harness; the official DeepSeek route is asked through `@deepseek-ai/dsh-llm-deepseek`'s listing request with the key its credential reference resolves to. Each route has `keyTestTimeoutMs`. The answer names each route and its result, never a key, an address or a provider's message. A listing answered with a success status and a body that is not a model list, such as a captive portal's page, reads as Could not test this key, never as working.
- **Recommendations** read each configured package's `package.json` `delo.connections` (see [Connections](#connections)) from the installed package; a package that is not installed is read from `registry` only when the request says `registry: true`, within `registryTimeoutMs`, and is `unknown` otherwise. The registry request is this route's only network request.
- **Adding a folder and cloning** are present only while upstream's workspace registry is. A `connection/request` listener refuses, before the body is read, any request to the three loopback-only routes that did not arrive on the loopback listener under a loopback `Host` (the listener the mounted `homeAuth` service reports, and `@delo/home-auth`'s `isLoopbackHost`), and every such request while no `homeAuth` service is mounted: 403 `{ error: 'LOOPBACK_ONLY' }`, because a workspace decides what the model may write and only the person at the computer chooses it. Each folder is held against `workspaceLocationProblem` from `@delo/home`, with the Delo home resolved from the environment: the filesystem root, the home directory itself, the Delo home or the stock home `~/.dsh`, a folder inside either, a folder that contains either, and a relative path are refused with 422, and nothing is registered or cloned. A Delo home that cannot be resolved answers 500 and a request that cannot be read answers 400. Logs carry an error's code, never a path, address or Git's output.
- **Cloning** ([`src/clone.ts`](src/clone.ts)) takes only `https://`, `ssh://` and `user@host:path` addresses; a local path, `file://`, `ext::`, another scheme, a value led by `-`, a host led by `-`, and whitespace or control characters are refused with `url-form`, and an `https://` address with a user name or password in it with `url-credentials`, before Git runs. The new folder's name is one plain name (`name-form` otherwise), and the folder must not exist or must be empty (`not-empty` otherwise). One clone runs at a time (`busy`), claimed before the first wait. Git runs in the harness's process as the person, never inside a chat, as `git clone --progress --no-recurse-submodules -- <url> <folder>` with no shell, stdin closed, and an environment that keeps only where it runs, who runs it and how it reaches the network, with `GIT_TERMINAL_PROMPT=0`, empty `GIT_ASKPASS` and `SSH_ASKPASS`, `SSH_ASKPASS_REQUIRE=never`, `GCM_INTERACTIVE=never`, `ssh -o BatchMode=yes` and `GIT_ALLOW_PROTOCOL=https:ssh`, so a repository that needs a sign-in fails at once with `sign-in` and a redirect cannot change the transport. Git also gets `-c core.hooksPath=/dev/null`, `-c filter.lfs.smudge=`, `-c filter.lfs.process=`, `-c filter.lfs.required=false`, `GIT_LFS_SKIP_SMUDGE=1` and a `--template` whose `info/attributes` unsets `filter` for every path during checkout (the file is removed from the clone afterwards); an SSH host key that cannot be verified fails with `host-key`. Git's own credential helpers still answer from what the person saved. After `cloneTimeoutMs` the clone is stopped with `timeout`; on POSIX Git leads its own process group, so the stop also ends its transport helpers. A failed clone removes the folder its own Git created, or empties a folder that was empty before. A finished clone is added as a workspace as a chosen folder is; `add-failed` says the clone is on disk but could not be added. The 16 newest outcomes are kept for `cloneStatus`; stopping the plugin stops a running clone.
- **No-key banner.** An entry in `conversation.input.dock` (id `delo-onboarding.key-banner`, order 5, above the starter prompts) shows "Add a model key to start chatting" with a button that opens Settings → Models (`ctx.settingsShell.openSection('models')`) while the key test finds no provider that works and none that might: every route is `no-key`, `rejected` or `untested`, or there is none. An unreachable route, a failed test or a key test that cannot be read shows nothing. The banner asks once when the box mounts and every 5 seconds while it shows, so it leaves once a key is added; it never opens a dialog. It registers only while the Delo look is on.
- **First chat.** When the dialog opens it calls `ctx.workspaces.initializeDefault()` once, which the host answers with the existing default workspace and creates one only while it holds no workspace and no chat. Start a chat calls `ctx.uiWorkspace.openWorkspace` with the chosen workspace and writes the opened chat's id to `starterSession` and the folder's kind to `starterKind` before the chat is shown. Where the lookup resolves nothing and other workspaces exist and the person chose none, the workspace UI's own New Session applies. Without `ctx.uiWorkspace`, New Session applies and no prompts follow. While the dialog shows it holds the workspace UI's `defaultWorkspaceFailed` notice through `ctx.uiWorkspace.holdDefaultWorkspaceNotice()`; when it closes the notice is dropped if Workspace said there is no default workspace, and shows otherwise. The prompts are an entry in `conversation.input.dock` (id `delo-onboarding.starters`, order 10); a chip calls `setDraft` on that chat's input and focuses the box only for a pointer that can hover. While `starterSession` is `pending`, the first empty chat whose input dock mounts takes the prompts.
- **`ctx.deloOnboarding.registerStep(step)`** adds an `OnboardingStep` (`id`, `order` 600 to 999, `title`, `component` taking `next`) and returns its disposer; a step with an earlier step's id replaces it.
- **Copy** is in English and Chinese ([`src/client/locales.ts`](src/client/locales.ts)) under the namespace `deloOnboarding`; another studio language falls back to English. The Plugins page names the plugin from [`locale/`](locale/en.json). CSS uses theme tokens only. Below 768 px the dialog is the whole window, the list of steps becomes a count with a bar, and the footer stays at the bottom; rows grow to 44 px for a coarse pointer.

## Connections

A plugin says which of a person's connections it is for in its own `package.json`, and the Recommended plugins step reads that field and nothing else:

```json
{
  "name": "@scope/codex-quota",
  "delo": { "connections": ["agent:codex"] }
}
```

An id is `provider:<id>` for a model provider route as Settings → Models lists it (such as `provider:deepseek-official`), `agent:claude-code` or `agent:codex` for a coding agent signed in on this computer, or `tool:tailscale` once Tailscale is installed; at most 16 per package. A package that declares none fits any setup. The repository's package-state gate accepts the field on a Delo package.

## Configuration

The row `delo-onboarding` has these fields ([`src/config.ts`](src/config.ts)), validated when the configuration loads. The first five are volatile and change while the studio runs.

| Field | Default | Meaning |
| --- | --- | --- |
| `done` | `false` | Whether the person finished or skipped onboarding. |
| `step` | empty | The id of the step reached. |
| `starterSession` | empty | The chat whose empty state offers the starting prompts; `pending` for the next empty chat. |
| `starterKind` | empty | What that chat's folder holds: `empty`, `code`, `files`, or empty for the general prompts. |
| `plugins` | empty | Up to eight npm package names the Recommended plugins step offers. With none, the step is left out. |
| `registry` | `https://registry.npmjs.org` | The `https://` npm registry a package that is not installed is read from, only when the person asks. |
| `registryTimeoutMs` | `10000` | The most time the registry requests may take together, 1000 to 60000. |
| `keyTestTimeoutMs` | `15000` | The most time one provider's key test may take, 1000 to 60000. |
| `cloneTimeoutMs` | `600000` | The most time a clone may take, 10000 to 3600000. |

[`@delo/bundle-studio`](../bundle-studio/README.md) sets `plugins` to four experimental plugins that ship with DeepSeek Harness: session search, the terminal bundle, the worktree tool and session titles.

## Limits

- **Delegation consent.** Adding Claude Code or Codex asks for the two presses on its card. Later, an agent that starts from a chat is subject to Delo's own delegation consent, which the Agents step describes: Delo asks on this computer first unless the person allowed it for that workspace, a phone cannot answer, read-only chats never start one, and a run stays in the chat's workspace and stops after 30 minutes. This plugin does not implement that consent; the step's copy has to follow it.
- **Key results.** Upstream's pi-ai discovery reports a refused key and an unreachable endpoint with the same code, so such a route shows Could not test this key for either, where the official DeepSeek route tells The provider rejected this key from Could not reach the provider.
- **Connections.** No shipped plugin declares connections yet, so every seeded plugin fits any setup. No Codex quota or Command Code plugin was found to recommend.
- **Folder chooser.** Onboarding's refusals cover only the folders it adds or clones into. Upstream's own add-workspace flow and `workspace.create` register any existing directory; under Delo, every shell command with write access in a workspace that is, lies inside or contains the Delo home then fails with `HOME_IN_WRITABLE_ROOT`. The chooser has no path field and no way to show hidden folders.
- **Clone.** A clone needs Git on the harness's `PATH`. A clone runs with hooks and every `filter` attribute off, so no hook or smudge or process filter from the person's Git configuration runs during checkout; filters and hooks run later, when the person uses Git in the folder. An `https://` address with a user name or password in it is refused with `url-credentials`. On POSIX, Git leads its own process group, so a harness that exits without stopping the plugin leaves a running clone to finish on its own. A repository that needs a sign-in the person has not saved is cloned in a terminal and then chosen as a folder; the guide never asks for a password or passphrase.

## Tests

`node_modules/.bin/vitest run --config delo/vitest.config.ts --maxWorkers=2 delo/packages/plugin-onboarding/` runs the specs; add `--coverage.enabled --coverage.provider=v8 --coverage.reporter=text --coverage.include='delo/packages/plugin-onboarding/src/**'` for coverage, which is complete.

- [`tests/host.spec.ts`](tests/host.spec.ts) checks the configuration, the record reader with a missing, malformed, oversized, directory-named and hostile file, and the routes the harness mounts.
- [`tests/workspace-route.spec.ts`](tests/workspace-route.spec.ts) checks the add-workspace route and the loopback guard on it and both clone routes: a request a reach listener admitted, one under a non-loopback `Host`, one the service cannot place and any request while no `homeAuth` service is mounted are refused with 403 before the route.
- [`tests/clone.spec.ts`](tests/clone.spec.ts) checks the addresses and names a clone takes and refuses (`file://`, `ext::`, `-`-led values and hosts), each refusal before Git runs (locations Delo never adds, also through a symlink, a folder that holds something, a second clone), 400 and 500 answers, progress, timeout, cleanup, the failure classes, the environment, and real Git: a server that asks for a sign-in fails with `sign-in` without waiting, `http`, `file` and `ext` transports are refused, and an abort stops Git.
- [`tests/readiness.spec.ts`](tests/readiness.spec.ts), [`tests/key-test.spec.ts`](tests/key-test.spec.ts) and [`tests/recommend.spec.ts`](tests/recommend.spec.ts) check the sign-in and Tailscale checks, the folder kind, each key result against a local listing server, and the declared connections from disk and the registry.
- [`tests/steps.client.spec.tsx`](tests/steps.client.spec.tsx), [`tests/workspace.client.spec.tsx`](tests/workspace.client.spec.tsx), [`tests/bundles.client.spec.tsx`](tests/bundles.client.spec.tsx), [`tests/guide.client.spec.tsx`](tests/guide.client.spec.tsx) and [`tests/dialog.client.spec.tsx`](tests/dialog.client.spec.tsx) check each step, the radio groups' tab stop and keys, the agent confirmation, that bundles install only on a press, the clone form and its states, the guide's shared state, the notice acknowledgement, resume, skipping, the steps left out and where focus lands.
- [`tests/chooser.client.spec.tsx`](tests/chooser.client.spec.tsx) and [`tests/focus.client.spec.tsx`](tests/focus.client.spec.tsx) check the step's own chooser and focus; [`tests/plugin.client.spec.tsx`](tests/plugin.client.spec.tsx) the registrations, Show again, the record loader, the default workspace lookup and the first chat; [`tests/starters.client.spec.tsx`](tests/starters.client.spec.tsx) the starting prompts; [`tests/key-banner.client.spec.tsx`](tests/key-banner.client.spec.tsx) the no-key banner; [`tests/previews.spec.ts`](tests/previews.spec.ts) the preview colours; and [`tests/locales.spec.ts`](tests/locales.spec.ts) the English and Chinese copy.
