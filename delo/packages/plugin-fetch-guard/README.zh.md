# @delo/plugin-fetch-guard

[English](README.md) | 中文

## 摘要

`@delo/plugin-fetch-guard` 提供 `fetchGuard` 服务，[`@deepseek-ai/dsh-web-fetch-http`](../../../packages/web/web-fetch-http) 的 `http` 抓取提供方在每一次跳之前——初始请求与每个重定向目标——都会询问它。提供方先解析跳的主机名，因此守卫分类的是连接实际会使用的地址，而不只是名称；拒绝会抛出一个类型化错误，作为抓取的失败向外传播，模型原样读到它，并且不建立任何连接。该服务对消费方是可选的：提供方在每一跳用 `ctx.get()` 读取它，因此挂载或卸载本插件会改变下一个请求，而无需重新加载提供方；没有挂载守卫时，每一跳不做解析。stock 的组合不挂载本插件，因此 stock 的 `web_fetch` 会抓取回环与私有网络目的地。这就是 Delo 的 C16 开关 `fetch_guard`，在对等组合中处于关闭状态。

## 约定

- **拒绝矩阵。** 开关打开时，解析到的任一地址属于回环地址（`127.0.0.0/8`、`::1`）、链路本地地址（`169.254.0.0/16`、`fe80::/10`）、RFC1918 私有地址（`10/8`、`172.16/12`、`192.168/16`）、IPv6 唯一本地地址（`fc00::/7`）或未指定 IPv4 地址（`0.0.0.0`）时，守卫拒绝该跳。IPv4 映射或 IPv4 兼容的 IPv6 目的地按其低半部分所写的 IPv4 地址分类。分类器无法解析的地址同样被拒绝：说不清连接会去向何处的守卫不会放行。其余地址全部放行（[`guard.ts`](src/guard.ts)）。
- **拒绝。** 被拒绝的抛出 `FetchGuardRefusedError`，带有代码、请求所写的主机名，以及只点名这两者的消息——不含解析到的地址，不含接口名——因此拒绝可以原样引用进工具结果，而不泄露多出被请求内容的信息。
- **每一跳。** 守卫位于提供方的重定向循环之外：初始请求与每个同源重定向目标都在其连接建立之前被解析并检查，因此在两跳之间重绑定到私有地址的主机名会在那一跳被拒绝。
- **开关关闭。** `enabled: false` 是默认值，也是对等值。此时插件不提供任何服务，提供方在每一跳读到它不存在，于是不加守卫地运行，每一跳也不做主机名解析：抓取与 stock 逐字节相同。
- **消费方。** 服务按名称读取，而不是导入：任何提供 `fetchGuard` 的插件都会守卫提供方的每一跳，守卫变化时提供方无需重新加载。`web_fetch` 工具以与其他抓取失败相同的类型化错误报告拒绝；守卫只覆盖 `http` 提供方——命令，以及你配置的代理或远程抓取提供方，都在它之外。

<a id="configuration"></a>

## 配置

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `enabled` | `false` | 在每次连接建立之前拒绝拒绝矩阵中的目的地。关闭时——C16 开关 `fetch_guard`——插件不提供任何服务，`web_fetch` 的行为与 stock 相同。 |

<a id="known-limitations"></a>

## 已知限制

- 守卫分类的是 `node:dns` 为该跳主机名解析到的地址；若解析器对提供方查询的回答与连接自身解析不同，连接仍可能开往守卫从未见过的地址。提供方以 `lookup(..., { all: true, verbatim: true })` 解析，与 undici 首先连接的地址相同。
- 拒绝只点名主机与原因，不点名解析到的地址；一跳因若干地址中的一个被拒绝时，报告既不指出是哪一个，也不列出其余的。
- 守卫只覆盖 `http` 抓取提供方。`deepseek` 提供方自己的 API 调用与代理策略都在它之外。

<a id="tests"></a>

## 测试

[`tests/guard.spec.ts`](tests/guard.spec.ts) 覆盖脱离 Cordis 的拒绝矩阵：每个被拒绝的网段与拼法、放行的貌似公开的地址，以及类型化拒绝的各字段。[`tests/service.spec.ts`](tests/service.spec.ts) 挂载服务，覆盖它的开关、它的拒绝，以及卸载对名称的影响。[`tests/provider-guard.spec.ts`](tests/provider-guard.spec.ts) 把真实的提供方插件与守卫插件作为兄弟挂载，并 mock 掉 `node:dns` 与 `undici`——不运行任何网络——证明整条链：连接之前的主机名解析、任何连接之前的类型化拒绝、重绑定重定向跳的拒绝、按名称被提供方询问的作为兄弟挂载的 stub 守卫插件、晚于提供方挂载的守卫从下一跳起被读取，以及完全没有解析的不加守卫的运行。
