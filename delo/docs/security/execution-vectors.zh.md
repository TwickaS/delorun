# 每种执行向量的信任

[English](execution-vectors.md) | 中文

Delo 尚未发布；本页描述第一个版本。它说明 Delo 的每种运行方式实际强制了什么、不能强制什么，以及与同版本 stock DSH 的对比。第一版中尚不存在的向量会明确标注。

[威胁模型](threat-model.zh.md) 给出各方、资产与每道防线及其契约；本页是执行侧的视图。[信任指南](../guide/trust.zh.md) 说明每一方能看到或做什么。

## 向量

姿态由两件事决定：**模型命令在哪里运行**（执行向量）和 **谁能访问 studio**（reach 向量）。两者可自由组合。

| 执行向量 | 在哪里运行 | 由什么强制 | 第一版 |
| --- | --- | --- | --- |
| 原生工作区 | 命令直接在你的账户中运行，由操作系统限制 | Linux 上的 bwrap 或 Landlock、macOS 上的 Seatbelt、Windows 的 ACL runner——由内核拒绝，而不是工具 | 是 |
| Docker 工作区（S2） | 命令在每工作区一个容器中运行 | 容器的命名空间、能力、cgroup、挂载与网络，以及启动后的容器内探测门 | 是，需引擎提供所需限制 |
| reach 监听器（Delo 托管） | 同一组路由暴露在公网地址上 | C4 准入步骤：身份、Host、Origin、SNI、启动令牌与服务端会话 | 不在第一版 |
| reach 监听器（你自己的 tailnet） | 同一组路由暴露在你的 Tailscale 地址上 | Tailscale 的设备身份加上同一套 C4 准入步骤 | 不在第一版 |

**自托管 home** 不是独立向量：它是你自己机器上的同一个 home 目录，可与上面四种组合。

## 各项保证，按向量

下表列出一个人合理期待的保证。"Stock" 指同版本的 stock DSH。

| 保证 | Stock | 原生 | Docker（S2） | Reach（计划中） |
| --- | --- | --- | --- | --- |
| 受限命令不能写到工作区之外 | 是 | 是 | 是 | 不适用 |
| 受限命令不能读取 Delo 的 home（密钥、令牌、会话日志） | 否 | 是 | 是——home 未挂载 | 不适用 |
| 受限命令不能读取你账户的其余部分（`~/.ssh`、`~/.aws`、`/etc`） | 否 | 否——与 stock 一致 | 是——容器只看到工作区与自己的根 | 不适用 |
| 受限命令不能访问网络 | 否 | 否——与 stock 一致 | 默认是；工作区网络无法离开引擎 | 不适用 |
| 命令不能访问 Docker socket 或引擎主机 | 否 | 不适用 | 是——socket 从不挂载，桥接网关被阻断 | 不适用 |
| 模型对指令文件的写入需要一次说明效果的批准 | 否 | 是 | 是 | 是 |
| 添加 MCP 服务器需要一次说明命令的批准 | 否 | 是 | 是 | 是 |
| 定时任务不能投递到已改变权限预设的对话 | 否 | 是 | 是 | 是 |
| 模型不能在没有守卫的情况下改变沙箱模式 | 否 | 是 | 是 | 是 |
| 每条路由在登录前都返回 401 | stock 分派时没有准入门 | 不适用 | 不适用 | 是 |
| 会话在服务端、哈希保存、可撤销 | 否——同用户可读密钥签发的无状态 30 天 cookie | 不适用 | 不适用 | 是 |
| 发布在运行前完成签名校验 | 否 | 是 | 是 | 是 |
| 更新会报告、快照并可回滚 | 否——静默禁用不兼容插件 | 是 | 是 | 是 |
| 归档是封闭数据格式，从不求值代码 | 否——加载时用 `new Function` 求值 `!!js` | 是 | 是 | 是 |
| 默认安装不发送关于你的任何数据 | 否——默认开启会话日志上传与产品分析 | 是 | 是 | 是 |
| 插件被固定版本、校验完整性与可撤销 | 否 | 第一版不提供 | 第一版不提供 | 第一版不提供 |

Docker 一列假设引擎提供门所需的全部限制。`delorun verify` 与工作区自己的启动报告会说明它不满足时的情况，而无法证明某项属性的工作区会被停止，而不是被启动。

## 组合

- **仅原生。** 操作系统沙箱就是边界。home 对命令隐藏；账户其余部分与网络不隐藏，与 stock 完全相同。操作系统支持沙箱且你希望攻击面最小时选它。
- **仅 Docker。** 容器就是边界。工作区是唯一可写的宿主路径；home、Docker socket 与机器其余部分都不可达，工作区网络也没有通往你机器的路由。运行不受信任的模型或插件、或操作系统沙箱不可用时选它。代价是需要 Docker 引擎与每工作区一个容器。
- **原生加 Docker。** 不同工作区可用不同向量。隔离是按工作区的：原生工作区仍与你的账户一样开放。
- **在任一向量之上加 reach。** reach 改变的是谁能与 studio 通信，而不是命令在哪里运行。被 reach 的 studio 仍在其工作区选择的向量中执行，监听器背后的每条路由在登录前都返回 401。不在第一版。
- **自托管 home 加你的 tailnet。** 远程访问优先选这一组合：路径中没有 Delo Run 的任何服务，流量走 tailnet，TLS 在你机器上终止，而 C4 准入步骤仍然运行。不在第一版。
- **自托管 home，仅本地。** 最简洁的信任故事：不打开监听器，除你主动要求的以外（模型请求与你启用的工具）没有任何东西离开机器。

## 自托管

自托管 home 是你在自己拥有并运维的机器上的 home 目录（`~/.delo`）。这对信任意味着：

- **密钥在你手里。** 模型凭据在你的机器上；Delo Run 无法访问。发布与目录主机会获知你的 IP 地址与你请求的版本——仅此而已。
- **操作系统由你负责。** 文件权限、全盘加密、备份以及谁能登录都归你。Delo 的保护是 home 的 0700/0600 布局加上沙箱的受保护 home 规则；它不是磁盘加密，也不防御你以同一用户运行的程序。
- **更新决定由你做。** 每次更新都会报告将改变什么、对配置做快照并在失败时回滚。自托管 home 可让安装器指向镜像；签名校验不依赖主机。
- **你可以自己核查。** `delorun verify` 报告发布的校验结果以及你的系统强制了哪些限制规则。

## 你自己的 tailnet

Tailscale 是 Delo 推荐的远程访问向量，因为信任边界仍然在你这边：

- **路径中没有 Delo Run 的服务。** 连接由 tailnet 承载；TLS 在你机器上终止。
- **设备身份来自 Tailscale。** Delo 的 C4 准入步骤仍要求 Host、Origin、SNI 匹配与服务端会话；tailnet 是增加一层，而不是替代。
- **tailnet 不是互联网。** 只有你的设备能看到 studio，而 tailnet ACL 决定其中哪些能连接。
- **它不改变什么。** 命令仍在工作区选择的向量中运行，fetch 守卫管的是 `web_fetch`，不是你的 shell。

## 与 stock DSH 对比

Delo 是加了 Delo 层的 stock DSH。在限制方面两者是同一机制——Delo 的沙箱就是上游的——因此有意义的差异是 Delo 层新增的那些，每一项都与其决策一起列出：

| | Stock | Delo | 理由 |
| --- | --- | --- | --- |
| home 保护 | 不向受限命令隐藏 home | home 对进程内工具与受限命令都是受保护读取 | C1 |
| Reach | 路由分派时没有准入门 | 每条路由、升级与兜底之前都有准入步骤 | C4 |
| Reach 会话 | 同用户可读密钥签发的无状态 30 天 cookie | 服务端、哈希、可撤销、绑定权威 | C5 |
| 权限同意 | 无 | 模式守卫，加上指令层、MCP、定时与 fetch 同意；在 parity 组合中关，在 Delo 组合中开 | C16、A101 |
| 发布 | 无校验 | 运行前校验签名、身份、透明日志条目与日志 | C2、C18 |
| 更新 | 静默禁用与重写 | 报告、快照、恢复与回滚 | C3 |
| 归档 | 加载时求值 `!!js` | 封闭数据格式，不求值 | C8 |
| 隐私默认 | 会话日志上传与产品分析默认开启 | 两者都关；你开启之前不会有数据离开 | A49 |
| 插件 | 不固定版本、无沙箱，且已明示 | 第一版相同，并明示；固定版本与撤销随插件索引落地 | A140 |

## 任何向量都不能防护的情况

以下限制在所有向量中都成立，在此明示而非隐含：

- **以你的用户运行的程序。** 它能读取 `~/.delo`、凭据文件、会话日志与其余一切。这就是操作系统账户的含义。
- **被攻陷的操作系统，或持有你账户的实时攻击者。** 同类。
- **没有任何静态加密。** Delo 的存储在 0700/0600 下是明文；全盘加密由你控制。
- **获得批准的模型动作。** 批准说明会发生什么；一旦批准，动作就会发生。同意约束的是能请求什么，而不是已批准的动作是否明智。
- **插件。** 插件以你的权限作为受信任代码运行。安装它即授予该权限。
- **通过命令的网络出口。** fetch 守卫管的是 `web_fetch`；除非向量是 Docker 工作区，shell 命令可以访问网络。
- **远端主机获知的信息。** 模型提供方看到你的请求；发布与目录主机看到你的 IP 与版本。
