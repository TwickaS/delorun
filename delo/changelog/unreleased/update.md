area: Install and update
section: Added
---

- `delorun update` fetches the newest release on your channel, checks it, shows what it would change in your profile before anything changes, and applies it once you confirm. Running chats finish first, and an update whose new version fails its health check goes back on its own and names the check it failed; a plugin the report disables does not count as a failure when its rows are gone, and neither does a Docker socket that appeared, or a Docker context you switched, since Delo started; a new version whose sandbox would protect less than the one it replaces goes back too. Updates come from the channel the launcher that installed Delo was built for; no environment variable or setting moves it. Delo keeps your profile's history with git, so an update and a rollback say so and stop before they fetch or change anything when git is not installed. A release that does not verify, a release channel that cannot be reached, or an update the home process could not finish, ends with a sentence that says what happened and what you can do.
- While an update or `delorun stop` waits for running chats to finish, a new message starts no turn: the chat shows that Delo is updating and that the message was not sent, so you send it again once Delo is back, and the wait ends once the running chats end. Background jobs count as running chats, and stopping with `--now` cancels them too.
- Before an update applies, Delo works out what the new release would change in the person's profile: each plugin it would disable or remove and why, judged exactly as Delo judges a plugin when it installs or starts one, so a plugin that names its DeepSeek Harness versions only through its peer dependencies is not shown as kept when the next start would turn it off, each bundle that leaves the bundle list or cannot load, and each row and Include that loads a plugin the update disables. The report marks every prediction it could not fully make from metadata it could read, so those are never counted as safe, and it shows both the CLI home's and the desktop Host's versions and update states, because the two update independently. Nothing applies until the person confirms, and `delorun update --yes` will not confirm a report that disables or removes anything or rests on metadata Delo could not read.
- When an update changes the format of your chat data, the report says so and Delo copies your chats and workspaces first, unless you choose to continue without the copy. Going back restores that copy and keeps the chats written since in a set-aside folder; nothing is deleted.
- `delorun recover status` lists the update you can go back from and every kept copy and set-aside folder with its size, `delorun recover rollback` goes back, `--profile-only` restores only your profile, and `delorun recover discard` removes a kept folder you no longer need.
- An update or a rollback checks every release against the release roots of the launcher that started Delo, so a root file replaced under the home is not trusted; a Delo started without its launcher refuses to update or roll back and says to start it with the launcher. A studio that takes long to shut down for an update is waited for instead of ending Delo in the middle of the switch, and one that does not shut down ends the update with nothing changed and Delo running again.
