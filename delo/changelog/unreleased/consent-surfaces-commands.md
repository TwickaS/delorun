- `delorun workspace full-access <folder> on` turns on full access for a folder after showing what it means and asking you to confirm at a terminal; `off` turns it off, and without a folder the command lists the folders with full access. When Delo runs, the studio counts the change at once. `delorun headless` in that folder can then run with full access.
- `delorun mcp list` shows the local MCP servers Delo is holding, what changed since you allowed each (a new server; its command, arguments, working directory or environment variables changed, naming the variables that changed; its command or folder now points to a different file or folder on this computer; the acceptance list could not be read; or, for a server you allowed before Delo remembered each server separately, a one-time review) the exact file that runs and the folder it runs in (on Windows also the command shell that runs a `.cmd` or `.bat` file), and why it waits, and whether you declined or revoked it, then the servers you allowed and when you allowed each. Each server is allowed on its own, so two servers started with `npx` never share an answer. Values of environment variables stay hidden, except for the ones that change what runs, such as `PATH` and `NODE_OPTIONS`. `delorun mcp accept <server>` shows the server's command and starts it after you confirm at a terminal, and `delorun mcp decline <server>` keeps it stopped until its command or settings change.
- `delorun mcp revoke <server>` shows an allowed server, and after you confirm at a terminal withdraws it and stops it; it stays stopped until its command or settings change or you accept it again, and your other servers stay allowed.
