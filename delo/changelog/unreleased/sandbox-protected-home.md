area: Safety and privacy
section: Security
---

- The sandbox keeps confined commands from reading or writing Delo's home and from connecting to the sockets of Delo's own services and of Docker, where the platform enforces it. A writable workspace that contains the home is refused for commands, and the file tools refuse to read, search or write inside it. A key file there stays out of reach of a command the agent runs.
- Searching the machine with `glob` or `grep` no longer reaches Delo's home: a search over a folder that contains it lists none of the home's files and prints none of their matched lines, so a pattern or a word that matched a key file there finds nothing. The search runs in the same sandbox as the agent's commands, so a folder the agent swaps for a link to the home while a search runs shows nothing of it either, and where the sandbox cannot run, the search fails instead of running unprotected. A session under full access still searches everywhere it reaches.
- Reading, editing, writing, creating or deleting a file with `read`, `read_image`, `str_replace_editor`, `edit`, `write` or `apply_patch` fails instead of reaching a file in Delo's home when a folder on its path is swapped for a link to the home between the check and the change.
- Tool output too long for a chat is saved in Delo's home, where `read` and `grep` in that chat can open it as the chat's notice says, while other chats and the commands the agent runs cannot. When the home cannot hold it, the output stays in the chat rather than going to a temporary folder those commands could read.
- The model can no longer offer you a file from Delo's home as a deliverable: presenting a file inside the home, or through a link that leads into it, is refused before the file is looked at, as opening it already was. A session under full access can still present any file it reaches.
- The sandbox records which of these rules each platform cannot enforce: Linux cannot block socket connections, and Windows does not limit reads.
- The Linux sandbox launcher refuses a grant path that names a symbolic link in any part and does not run the command, so a path swapped for a link after it was checked cannot widen what a command may touch.
- Under WSL, a command the agent runs in the sandbox can no longer start a Windows program through WSL's interop, by its path, by name or as a copy. Where the sandbox cannot use bubblewrap, its fallback cannot block this, so it refuses to run commands under WSL rather than leave this way out open.
- Under WSL, and on any other virtual machine whose system offers it, a command the agent runs in the sandbox can no longer open the virtual-machine connection to the host, which WSL's interop runs over. The sandbox also turns off io_uring for those commands, which could open that connection another way, so a program that needs io_uring fails there. A 32-bit program that opens network connections the old way cannot open any.
- A command the agent runs in the sandbox can no longer leave it through your session's services: it cannot start a program with `systemd-run --user` or through the session bus, reach the system bus, a tmux or screen server or the X server, or use your gpg-agent, keyring or the ssh-agent `SSH_AUTH_SOCK` names, because the sandbox hides their sockets. Where the sandbox cannot use bubblewrap, its fallback cannot hide them, so it refuses to run commands on a machine that has them rather than leave this way out open. A desktop's X server and a session bus started by `dbus-launch` can also listen on sockets no file names, which the sandbox does not hide.
- A command the agent runs in the sandbox can no longer reach Docker Desktop's control sockets under WSL or on Linux, through which it could change Docker Desktop's settings and act on containers, or the local control socket of Tailscale.
- A read-only command the agent runs in the sandbox now sees an empty `/tmp`, apart from a workspace that lies in it, as a command that may write already did, so it can no longer reach the sockets other programs keep in `/tmp`. A `glob` or `grep` search rooted elsewhere in `/tmp` finds nothing. With bubblewrap, io_uring is now off for confined commands on any machine with these session services, not only under WSL.
