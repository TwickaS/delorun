- Picking Full access in a chat whose folder does not have full access shows what it means before anything changes: one sentence on what agents can then do, one on the risk, and under Details the folder and what full access reaches: your files, Delo's home with its keys and tokens, the Docker supervisor and Delo's update channel. It is the only dialog the permission control shows for Full access, and it asks you to tick that you understand the risks before Allow full access is enabled. Allow full access records your answer and switches the chat; Cancel leaves it in the sandbox. In a folder that already has full access, or a chat without a folder, the same dialog asks "Switch this chat to full access?" with the same tick and records nothing.
- When an agent's request asks for full access, its approval card offers "Allow full access for this workspace": it asks the same question if the folder does not have full access, then switches the chat to full access so it stops asking, and allows the request. Once you rejected the request, or it ended, the action is greyed out and records nothing, also when you confirm the question it opened.
- Settings, Permissions lists everything you allowed, each with a one-click Revoke. Full access lists the folders that have it, where new chats start with full access; revoking puts the folder's open full-access chats back on the safer permission within a second, in every running profile, and the other folders sit behind a disclosure where you can allow it. MCP servers lists the local servers waiting for your OK, with what changed (a new server, or its command, arguments, folder or which environment variables changed since you allowed it, or the file or folder it points to changed), the servers you declined or revoked, which stay stopped and quiet until you allow them, and the servers you allowed, each remembered on its own; revoking one stops it until you allow it again. Each answer's result shows under the section's introduction.
- Review on a waiting MCP server says what allowing it does, the exact file it runs and the folder it runs in, and its risk, what changed, and under Details its command, arguments, folder, the file, command shell and folder they point to, and environment variables, showing a value only for variables that change what runs, such as `PATH`, `NODE_OPTIONS` or `LD_PRELOAD`. Allow and start starts it without restarting Delo, and if the file or folder changed since you looked, nothing is allowed and the review shows the new one; Decline keeps it stopped.
- When an MCP server waits for your OK, a notice names it, and "Review and allow this server" opens its review, then the next waiting server's.
- These answers are given only on the home's own computer. On a phone or another device, the approval card, the notice, Settings, Permissions and the full-access explanation say to approve at your computer and offer no button; the phone sees only the names of the waiting servers. With "Same as stock" prompts, Settings, Permissions says the profile does not ask, and the permission picker switches as DeepSeek Harness does.
